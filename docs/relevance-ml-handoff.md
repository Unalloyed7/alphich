# Relevance ML: контракт и подготовка данных (совместная работа)

Статус: **контракт v1 предложен, требуется подтверждение от разработчика `relevance_ml` перед runtime-интеграцией**. Этот PR добавляет только экспорт из локального Quality Lab. Ни один производственный классификатор пока не подключается, ничего не фильтрует и не вызывает LLM.

## Границы ответственности

| Наша зона (данные и интеграция) | Зона команды ML / AI |
| --- | --- |
| `scripts/relevance_dataset.py`, снимки исходных данных, человеческие метки, контроль версий и разбиение | `knowledge/src/alphich_kb/relevance_ml/`: features, train, evaluate, predict, модель |
| `scripts/quality_review.py`, UI, экспорт арбитража и независимая проверка | Промпт LLM-разметчика, teacher labels, модель и пороги |
| Read-only/shadow адаптер в `discovery.py` после согласования | Семантика `candidate` / `uncertain` / `low_priority`, калибровка `p_relevant` |
| Наблюдаемость, fallback к существующему отбору, диагностика пропусков | Аналитик/verifier, финансовые механизмы |

В этом PR **не редактируются** `discovery.py`, `financial_grounding.py`, `agent.py`, `service.py`, `schemas.py`, `knowledge/src/alphich_kb/relevance_ml/*`.

## Предлагаемый runtime-контракт

**Вход** классификатора: один неизменяемый снимок (JSON) на пару:

```json
{
  "pair_id": "sha256 идентификатор пары",
  "event_id": "id статьи",
  "company_id": "id компании",
  "news": {"title": "...", "text": "...", "published_at": "2026-10-11T12:00:00Z", "source_url": "https://..."},
  "company": {"features": [{"name": "okved_code", "value": "46.51"}], "snapshot_date": null, "verified_at": "2026-10-21", "unknown_exposures": ["operational_geography_not_verified"]},
  "versions": {"schema_version": "alphich-relevance-dataset-v1", "fixture_sha256": "...", "news_text_sha256": "...", "company_context_sha256": "..."}
}
```

`verified_at` означает дату проверки снимка экспертом, **не дату обновления исходного профиля**. Отсутствующая дата исходника или текст обозначается `null`, а не восстанавливается из URL, текущего времени или решения LLM. Отрасль/регистрация не доказывают операционную географию. Embedding E5 и числовые признаки строит ML-команда из полей входа; признаки LLM-учителя в них **не допускаются**.

**Выход** отдельной локальной модели (JSON, предложен для утверждения; машинно-читаемая схема — `docs/relevance-ml-prediction-v1.schema.json`):

```json
{
  "p_relevant": 0.67,
  "decision": "uncertain",
  "model_version": "local-model-id",
  "feature_version": "features-v1"
}
```

Инварианты: `p_relevant` — конечное число от `0` до `1`, откалиброванная (и отдельно проверенная) оценка вероятности экспертного класса **4–5**. Это **не бизнес-оценка 0–5** и не основание для публикации карточки. `decision` одно из `candidate`, `uncertain`, `low_priority`; пороги согласуем на validation, не подбираем на test. Версии непустые. В runtime будет записываться отдельно и результат последующего LLM. Отсутствие профиля/текста или невалидный output → legacy rules и пометка `ml_unavailable`, **не отказ от статьи**.

## Экспорт из существующего Quality Lab

Данные уже находятся **только на Mac**, не переносите автоматически в публичный GitHub и Cloud.ru. В существующей базе после `enrich` — 186 пар, 186 профилей и 6 пар с текстами (остальные пока без текста). Экспорт не изменяет SQLite и не выполняет запросов LLM.

Из корня репозитория после добавления файлов PR:

```bash
python3 scripts/relevance_dataset.py \
  --db data/private/quality-review.sqlite3 \
  --fixtures-dir knowledge/fixtures \
  --output-dir data/private/relevance-export-v1
```

Появятся `model_inputs.jsonl`, `human_labels.jsonl`, `manifest.json`. `model_inputs` **ни при каких условиях не содержит `grade`, `rationale`, `selected` или оценки учителя**. `human_labels` содержит только итоговые оценки двух экспертов/арбитра, если такие имеются; при 0 проверок `grade=null`. Модель не должна обучаться на `null` как на классе `0`.

Только при осознанной необходимости оценивать или использовать weak teacher-labels в **отдельной** экспериментальной ветке:

```bash
python3 scripts/relevance_dataset.py \
  --db data/private/quality-review.sqlite3 \
  --fixtures-dir knowledge/fixtures \
  --output-dir data/private/relevance-export-with-teacher-v1 \
  --with-teacher-labels
```

Это создаст **отдельный** `teacher_labels_PRELIMINARY.jsonl`. Предварительные 186 меток содержат лишь девять положительных (4–5), ни в коем случае не являются human gold и не допускаются в финальную независимую оценку как истина.

Экспорт хранит SHA-256 референсных `v2`/`v3` и останавливается, если fixture изменился после инициализации SQLite. Каждая пара имеет ID, время среза исходного набора предварительной разметки (fixture_as_of — это не дата экспертной проверки), ссылку, снимок подтверждённых признаков и версии; полные тексты/даты могут быть неизвестны. `readiness.eligible_for_training` истинно только при наличии текста, даты, проверенного контекста и human gold. Содержимое ограничено белым списком признаков из независимого `review_company_context.json`; дополнительные поля, финансовые CSV и токены не экспортируются.

Для строгой проверки новых компаний предусмотрен `--heldout-company U_235727`. Он помечает все её пары `company_holdout`, но **трёх компаний недостаточно для убедительного out-of-company теста**. Дополнительные компании нужны отдельно. Для контроля перепечаток используйте приватный JSON `--article-groups data/private/reprint_groups.json` в формате `{ "event_id_1": "story_abc", "event_id_2": "story_abc" }`; все варианты одного сюжета должны попасть в один split. Изменённые пересказы на разных сайтах не распознаются автоматически, поэтому без проверки групп тестовая оценка может быть завышена.

`manifest.json` содержит количество готовых записей, версии, контрольные суммы выходных файлов и разбиение train/validation/test на уровне группы статьи; враждебные или некорректные данные не должны проходить в обучение. **Не используйте малую/неполную выборку для заявлений о качестве модели.** Неполная разметка может экспортироваться для контроля процесса, но не называться эталоном.

## Очередность работ

1. **Вместе согласовать** вход/выход с ML-разработчиком и ошибки/fallback. Условно выбрать 30–50 пограничных пар около 3/4 для общей калибровки критериев (не выдавать совместную выборку за независимый тест).
2. **Этот PR** — read-only экспорт, разделение источников/teacher/human и версии данных; сохранить локальную SQLite; прогнать тесты без сети.
3. Следующий наш PR — удобное массовое получение разрешённых статей и их снапшотов с сохранением происхождения, улучшенный UI на том же Quality Lab, экспорт подтверждённых оценок. Не переносить данные в публичный репозиторий.
4. Вместе с ML-командой — расширение позитивных и сложных негативных примеров. Рандомизированную выборку настоящего потока и сложные контроли считать раздельно.
5. После появления обученной модели — **shadow-only интеграция** в `discovery.py`: записывать `p_relevant`, `decision`, версии и реальный итог legacy + LLM, не фильтровать; мерить пропуски grade 5, Recall(4–5), Precision@K, экономию (расчётную) и задержку.
6. Включать настоящий prefilter только после экспертной оценки, проверки задержки/CPU и бюджета, с отдельным random audit отсеянных. Fail-open к старой логике при любых ошибках. Никаких изменений `AI_AUTOMATION_ENABLED` этим PR.
