# Обучение фильтра бизнес релевантности

Модуль `knowledge/src/alphich_kb/relevance_ml` готовит пары «снимок компании — полный текст новости», получает предварительную разметку разрешённой LLM и обучает локальный классификатор. Цель модели — вероятность оценки **4–5 по принятой шкале 0–5**. Вероятность не переводится арифметически в бизнес-балл.

Первый вариант использует закреплённый E5 ONNX и логистическую регрессию с L2 на NumPy. Предсказание и обучение работают на CPU. Артефакт содержит JSON с коэффициентами, масштабированием и манифестом признаков; pickle и загрузка исполняемого кода не используются. Решения имеют статус `shadow`: подключение к боевому отсечению новостей остаётся отдельной интеграцией.

## Данные компаний и источники

Проверен весь CSV организаторов: 85 525 строк, 85 514 уникальных идентификаторов, 85 513 пригодных профилей. Все 12 противоречивых строк одного идентификатора исключены. Крупнейшие группы — торговля, недвижимость, профессиональная деятельность, строительство, общепит и информационные технологии. Полная таблица и проверенные архивы находятся в [исследовании источников](relevance-source-research.md).

`knowledge/relevance-sources.json` описывает 12 официальных и отраслевых источников. Источник и тематическая рубрика определяют распределение корпуса, а не метку значимости. Регион регистрации не используется как доказательство места операций. По уточнениям вебинара выручка организаторов — RUB за 2025 год, `1000` — заглушка. Без сегмента охват компании/группы остаётся неизвестным; величины не суммируются по группе и не доказывают денежный эффект события. Крупнейшие сегменты нельзя определить одним денежным порогом. CityName/RCName обозначают место обслуживания, а не доказанную географию операций. Prospect/Close Client могут оставаться в справочнике связанных организаций; основной пользователь — Client.

Сборщик скачивает разрешённые архивы, RSS и sitemap, сохраняет очищенные тексты, явные даты публикации и происхождение. Время скачивания и sitemap `lastmod` не заменяют дату публикации. Лимиты запросов, времени, байтов и числа статей действуют на каждый запуск. Очередь и ошибки сохраняются в приватной SQLite; законченные URL не загружаются повторно автоматически. Ограничение на долю одного источника и чередование источников поддерживают разнообразие.

## Запуск

Нужны зависимости `backend/requirements.txt` для сбора и `knowledge/requirements-rag.lock` для E5. Из корня `alphich` установите `PYTHONPATH=backend:backend/src:knowledge/src` для следующих команд. `backend/src` содержит общую семантику организаторских данных. Ключ модели не нужен для сбора, подготовки пар, обучения и предсказания.

Агрегаты всех компаний:

```bash
python -m alphich_kb.relevance_ml companies \
  --csv /путь/к/df_Uid_data_hack.csv \
  --output data/private/relevance-ml/company-census-v2.json
```

Один ограниченный запуск сбора, с общей целью 10 000 уникальных статей:

```bash
python -m alphich_kb.relevance_ml collect \
  --sources knowledge/relevance-sources.json \
  --db data/private/relevance-ml/news-corpus.sqlite3 \
  --goal 10000 --max-articles 500 --max-requests 1000 \
  --max-seconds 600 --max-bytes 300000000 --max-source-articles 1500

python -m alphich_kb.relevance_ml corpus-status \
  --db data/private/relevance-ml/news-corpus.sqlite3
```

Повтор команды `collect` продолжает очередь. 10 000 ссылок в ней ещё не означают 10 000 пригодных полных текстов. Недоступный источник, ошибка даты, дубликат и неподходящий жанр имеют отдельный статус.

Ускоренный сбор по разным сайтам с сохранением интервалов каждого издателя:

```bash
python -m alphich_kb.relevance_ml collect-job \
  --sources knowledge/relevance-sources.json \
  --run-dir data/private/relevance-ml/corpus-10k \
  --goal 10000 --workers 8 --max-seconds 3600 --rounds 4 \
  --published-after 2026-09-07 --published-before 2026-10-22

python -m alphich_kb.relevance_ml job-status \
  --run-dir data/private/relevance-ml/corpus-10k

python -m alphich_kb.relevance_ml export-links \
  --job-dir data/private/relevance-ml/corpus-10k \
  --output data/private/relevance-ml/news-links-v2.json
```

Общее окно этого примера — последние 45 дней до даты проверки. Для продолжения используйте замороженный `data/private/relevance-ml/corpus-10k/sources.json` и прежние границы. Каждый раунд ограничен часом; `--rounds 4` разрешает до четырёх последовательных ограниченных продолжений, с отдельным HTTP/байтовым бюджетом на раунд. Достижение цели, исчерпание очереди или отсутствие прироста останавливают продолжение. Разные `run-dir` для одного издателя одновременно не запускаются: интервалы сохраняются внутри задания. Тексты находятся в отдельных SQLite групп хостов, `state.json` и `progress.jsonl` содержат агрегированный прогресс. `export-links` создаёт проверяемый снимок ссылок, заголовков и дат без текстов статей.

Для архивного корпуса период расширен до **2025-01-01 — 2026-10-22** в отдельном задании `data/private/relevance-ml/corpus-10k-2025`. Прежний процесс остановлен; принятые статьи, очередь, robots и паузы издателей перенесены через SQLite backup. Старое задание за 45 дней сохранено. `lineage.json` содержит происхождение копии и число восстановленных статей: повторно используются только тексты с сохранёнными датами и доказательствами издателя, прошедшие новое окно и жанровые ограничения. Остальные прежние исключения по дате возвращены в очередь для проверки. Архивные статьи сохраняют исходные даты и не становятся актуальными новостями или размеченными примерами автоматически. `data/private/relevance-ml/current-corpus.json` указывает текущее задание.

```bash
python -m alphich_kb.relevance_ml job-status \
  --run-dir data/private/relevance-ml/corpus-10k-2025

python -m alphich_kb.relevance_ml collect-job \
  --sources data/private/relevance-ml/corpus-10k-2025/sources.json \
  --run-dir data/private/relevance-ml/corpus-10k-2025 \
  --workers 8 --rounds 4 --max-source-articles 2500 \
  --published-after 2025-01-01 --published-before 2026-10-22
```

После сбора подготовьте до трёх разных пар на статью: компания той же отрасли, смежной отрасли и случайной отрасли. Выбор компаний охватывает отраслевые группы и меняется воспроизводимо по seed. Ни одна из этих групп автоматически не получает положительную или отрицательную метку.

Для параллельного задания в следующей команде замените `--db ...` на `--job-dir data/private/relevance-ml/corpus-10k`. Экспорт читает уже сохранённые статьи и может работать одновременно со сбором.

```bash
python -m alphich_kb.relevance_ml sample \
  --db data/private/relevance-ml/news-corpus.sqlite3 \
  --companies-csv /путь/к/df_Uid_data_hack.csv \
  --as-of 2026-10-22T12:00:00+03:00 \
  --pairs-per-article 3 --limit 30000 \
  --output data/private/relevance-ml/pairs-v1.jsonl \
  --report data/private/relevance-ml/sampling-v1.json

python -m alphich_kb.relevance_ml inspect \
  --input data/private/relevance-ml/pairs-v1.jsonl
```

Замените `as-of` реальным моментом оценки. Значение в команде иллюстрирует формат. Для исторического корпуса нельзя выдавать текущий профиль за подтверждённый исторический снимок: архивная пара — условный разбор события относительно предоставленного профиля. Учитель `relevance-judge-v2-business-fit` оценивает бизнес-релевантность события независимо от возраста, отдельно выдаёт предварительные `timeliness`, `temporal_reason`, `temporal_quotes`, `valid_from` и `valid_until`. Даты должны присутствовать в дословных цитатах; явное истечение срока не может получить статус current. При отсутствии подтверждения актуальности требуется unknown. Высокий бизнес-балл архивной статьи не разрешает показать её в текущей ленте: действующий runtime отдельно проверяет доступность, применимость, период наблюдения и прогнозный горизонт. В production пока сохраняются консервативные окна 45/90 дней; это эвристика команды, а не требование организаторов.

## Разметчик

`teacher.py` формирует запрос из разрешённых входных полей. Предыдущие оценки и объяснения в него не передаются. Ответ содержит балл 0–5, механизм влияния, тип воздействия, географию, масштаб, применимость, действие и недостающие данные. Доказательства должны быть точными подстроками статьи и ID фактов предоставленной компании.

Валидатор отклоняет выдуманные цитаты, чужие факты, противоречия между высокой оценкой и неизвестной бизнес-применимостью, противоречащие явным датам временные статусы и отсутствие действия для пятёрки. Возраст статьи не понижает бизнес-балл автоматически. Отклонённый ответ остаётся без метки; он не превращается в ноль. Проверка структуры и цитат не устанавливает правильность экономического вывода или текущую силу нормы, поэтому метка имеет `origin=teacher`, `target=business_relevance`, `timeliness_is_provisional=true`. Старые метки `relevance-judge-v1` с ограничением по возрасту требуют новой разметки; обучение не принимает их как ту же цель.

Подготовить три запроса без оплаты:

```bash
python -m alphich_kb.relevance_ml prepare-labels \
  --input data/private/relevance-ml/pairs-v1.jsonl --limit 3 \
  --output data/private/relevance-ml/requests-v1.json
```

Платная команда использует **существующую общую PostgreSQL БД расходов**, например из контейнера на сервере. Самому алгоритму разметки БД не нужна: она нужна адаптеру `Provider` для атомарного учёта общего API-ключа. Запуск с ноутбука тоже возможен при доступе к той же БД; отдельная локальная SQLite не учитывала бы параллельные расходы сайта. Команда не сбрасывает бюджет, сохраняет неизвестные резервы и использует общий лимит команды не выше **500 ₽ за UTC-день**. Это лимит всех моделей и участников, а не отдельные 500 ₽ разметчику. По инструкции организаторов день обновляется в 03:00 МСК.

```bash
python -m alphich_kb.relevance_ml judge \
  --input data/private/relevance-ml/pairs-v1.jsonl \
  --output data/private/relevance-ml/teacher-batch-v1 \
  --batch-id relevance-pilot-v1 --limit 3 \
  --live --shared-ledger

python -m alphich_kb.relevance_ml export-labels \
  --batch-dir data/private/relevance-ml/teacher-batch-v1 \
  --output data/private/relevance-ml/teacher-labels-v1.jsonl
```

Перед запуском серверный процесс должен иметь корректные `DATABASE_URL` и `LLM_*`. Режим `--env-file` читает явно выбранный dotenv как данные. Каталог batch закреплён за входами, моделью и хешем промпта. Возобновление использует тот же ID платного вызова; таймаут не порождает автоматический новый запрос. Бюджет партии не приравнивается к числу примеров: начните с нескольких пар и фактических квитанций общей БД.

## Разметка при бюджете 500 ₽ в день

Снимок на 22 октября: собрано 10 000 полных текстов; после объединения известных перепечаток подготовлено 29 787 пар — 9 929 статей по три компании. Это пул кандидатов для разметки. Не требуется оплачивать оценку каждой пары до первого обучения. Архивные статьи остаются учебными примерами со своими датами.

Предлагаемое распределение — до 400 ₽ на разметку и 100 ₽ на сайт. Это план расходования, **не реализованные независимые подлимиты**: действующий Provider атомарно защищает общий дневной лимит 500 ₽. Если сайту нужно больше, объём разметки уменьшается. Изменение env не сбрасывает уже потраченные суммы и неизвестные резервы. При прежнем серверном лимите 100 ₽ оператор применяет конфигурацию 500 ₽ штатным механизмом `LLM_APPLY_CONFIGURED_BUDGET=1` и обновляет окружение всех платных worker: процесс со старым лимитом может снова ограничить общий ledger.

Порядок работы:

1. Выполнить подготовленные десять пар, по одной на источник. Измерить оплаченные токены, все известные начисления, число валидных меток и ошибки. Цена валидной метки включает оплаченные неудачи. При неизвестном начислении не считать его нулём и не повторять запрос с новым ID. Следующая партия разрешается только после просмотра этого результата.
2. Собрать начальные 400–800 разнообразных пар в пределах фактического остатка. Балансировать отрасли, регионы, размер компаний, источники, типы событий; не подставлять нули для случайных компаний или несовпадения тематики. Целевой размер — стартовый эксперимент, не гарантия качества. Отдельно собрать достаточное число положительных 4–5, иначе модель выучит преимущественно отрицательный класс.
3. Обучить имеющийся E5 + логистическую регрессию локально и получить теневые оценки всего пула. Сохранять предсказания отдельно от teacher-меток и человеческого gold. Классификатор учится порогу 4–5, а не восстанавливает точный балл 0–5.
4. Следующие партии по 100–200 выбирать по неопределённости, недопредставленным сегментам, случайному контролю и противоречиям с потенциально критическими событиями. Сравнивать с обычным случайным отбором. Автоматический цикл такого выбора пока **не реализован**. [Active learning](https://proceedings.mlr.press/v16/settles11a.html) позволяет выбирать информативные примеры; [современная проверка](https://arxiv.org/abs/2403.15744) показывает, что выигрыш зависит от условий и не гарантирован.
5. Люди независимо проверяют отложенные пары без показа ответа LLM. Ориентир 300–500 пар, два проверяющих и согласование спорных. Разделять статьи, перепечатки и компании между обучением и независимой проверкой. Обогащённый набор критических событий оценивать отдельно от обычной ленты. До такой проверки локальная модель не отбрасывает новости окончательно.

Объём в день рассчитывается как `floor(доступный бюджет / цена валидной метки)`. При условных 400 ₽ для разметки:

| Измеренная цена валидной пары | Пар в день |
| --- | ---: |
| 0,10 ₽ | 4 000 |
| 0,25 ₽ | 1 600 |
| 0,50 ₽ | 800 |

Это сценарии, **не тариф шлюза**. В локальном журнале прежних задач 158 успешных вызовов GLM дали среднее 0,071376 единицы квитанции при среднем входе 3 628 и выходе 168 токенов. Новый учитель имеет другой промпт и более длинный JSON. Коэффициент `LLM_RECEIPT_RUB_PER_UNIT=1` — действующая настройка учёта; официальная инструкция устанавливает 500 ₽/день, но не публикует тариф токенов или однозначное описание валюты квитанции. Нельзя выдавать эту историческую среднюю за подтверждённую рублёвую цену новой разметки. Пилот сохраняет коэффициент и явно маркирует единицы учёта.

Дополнительная экономия — один текст статьи и три профиля в одном запросе. Для всего текущего пула это уменьшило бы количество вызовов с 29 787 до 9 929, но не расходы ровно втрое: повторяющийся вход сокращается, три ответа остаются. Такой протокол пока **не реализован**; нужны отдельная схема нескольких оценок, сохранение доказательств каждой пары, проверка достаточной длины ответа и обработка длинных статей. Компактные локальные псевдонимы фактов вместо повторения длинных ID также требуют обратного отображения в исходные доказательства.

### Локальная генеративная модель

На текущем MacBook Air M2 с 8 ГБ общей памяти E5 и небольшой классификатор пригодны для CPU. GLM-5.3-Flash имеет **320 млрд параметров всего, 18 млрд активных**: около 160 ГБ даже для теоретических 4-битных весов, до памяти движка и контекста. Малое число активных параметров не уменьшает требуемую память до модели 18B. [Официальная карточка GLM](https://huggingface.co/zai-org/GLM-5.3-Flash).

Более компактный разрешённый вариант — Gemma-4-26B-A4B-it: официальный Q4_0 файл текстовых весов занимает **14,4 ГБ**. Оценка для короткого контекста — GPU с 24 ГБ памяти либо около 32 ГБ общей RAM; это ориентир для проверки, не наш измеренный минимум и не обещание скорости. Если такая машина уже есть у команды, сравнить модель на 30–50 проверенных парах. На текущем Mac 8 ГБ и сервере без GPU перенос генеративного разметчика не даёт практичной экономии. [Официальный файл Google](https://huggingface.co/google/gemma-4-26B-A4B-it-qat-q4_0-gguf/tree/main).

Малые модели на 2–4B могут технически поместиться, но их нет в текущем разрешённом списке генеративных LLM. Разрешение локальных эмбеддингов не распространяется автоматически на любой генеративный разметчик.

По [документации Z.ai](https://docs.z.ai/guides/vlm/glm-5.3-flash) у GLM-5.3-Flash thinking не отключается; короткий видимый JSON не доказывает малую стоимость генерации. [Qwen3.6](https://huggingface.co/Qwen/Qwen3.6-35B-A3B) поддерживает non-thinking, но синтаксис и доступность проверяются именно на шлюзе организаторов. Не менять параметры работающего gateway по документации другого сервинга без проверки. Выбор учителя делается по качеству на проверенных парах и цене валидной метки, а не по названию Flash.

Обновлённый приватный пилот находится в `data/private/relevance-ml/labeling-handoff-v2-budget500/README.txt`. Пакет содержит десять пар и изолированный Python overlay без API-ключей. Он не сбрасывает общий бюджет и не выполняет платных вызовов при `--check`.

## Обучение и оценка

Признаки `relevance-features-v2-business-fit` включают E5 компании и всех фрагментов статьи, их произведение, абсолютную разность, косинусные признаки, роль и маски известных/неизвестных полей. Возраст и наличие даты публикации исключены из числовых признаков; будущие даты по-прежнему отклоняются. Заявленный масштаб выручки включается как `log1p` только при явных RUB/2025, с отдельным признаком известности охвата; без метаданных число не используется, `1000` не устанавливает наличие выручки. Число не включается в текст эмбеддинга. Префикс `query:` применяется к обоим текстам для обучения классификатора; это соответствует рекомендации [карточки E5 для linear probing](https://huggingface.co/intfloat/multilingual-e5-base). Все фрагменты текста входят в агрегацию; превышение максимального размера отклоняется без скрытого усечения. ID компании, ссылки на доказательства, оценки, объяснения и временные оценки учителя не входят в обучаемые признаки. Прямо написанные в статье даты могут оставаться в E5: исключение отдельного признака возраста не гарантирует полную независимость модели от временных формулировок.

Для обучения нужны оба класса: оценки 0–3 и 4–5. Предварительные LLM-метки требуют явного `--allow-teacher`:

```bash
python -m alphich_kb.relevance_ml train \
  --input data/private/relevance-ml/teacher-labels-v1.jsonl \
  --allow-teacher --split article \
  --output-dir data/private/relevance-ml/model-v1

python -m alphich_kb.relevance_ml predict \
  --input data/private/relevance-ml/pairs-v1.jsonl \
  --model data/private/relevance-ml/model-v1/model.json \
  --output data/private/relevance-ml/predictions-v1.json
```

Масштабирование обучается только на train. Все пары статьи, её известные редакции, переданные кластеры перепечаток и точные копии держатся в одной части выборки. Глобальный экспорт объединяет связанные кластеры, в том числе через общую перепечатку. Поиск похожих текстов остаётся эвристикой и может пропустить пересказ; независимый набор дополнительно проверяется на такие совпадения. Режим `--split company` требует одновременно независимых компаний и статей; на полностью связанном наборе он честно отклоняет невозможное разбиение. Хронологическую проверку на будущих публикациях нужно готовить отдельно; случайное разбиение по статьям её не заменяет.

Отчёт содержит precision/recall, матрицу ошибок, average precision, precision@K, recall при ограниченном числе кандидатов, пропуски пятёрок, Brier/ECE и число положительных примеров. При отсутствии положительных recall равен `null`. Экономия рублей оценивается по реальному журналу интеграции, а не из предположения, что каждый кандидат обязательно вызвал бы модель.

Порог 0,5 — технический исходный параметр. `--min-recall` разрешён только при отдельной человеческой validation с двумя проверяющими и согласованием/арбитражем; окончательный test не используется для подбора. [Документация по выбору порога](https://scikit-learn.org/stable/modules/classification_threshold.html) отдельно подчёркивает независимость данных для его настройки.

Независимую проверку выполняют люди через [существующий инструмент](quality-review.md). Результаты на LLM-метках описывают согласие с учителем. Они не измеряют качество бизнес-решений: [исследование LLM-as-a-Judge](https://arxiv.org/abs/2306.05685) описывает ограничения и ошибки таких судей.

## Передача коллеге

Коллега готовит независимую человеческую разметку и адаптер вызова классификатора из worker. Вход — каноническая пара, выход — `p_relevant`, `decision`, `model_version`, `feature_version`, `limitations`. Сначала сохраняются теневые предсказания без изменения существующего отбора. `uncertain` направляется на дальнейшую проверку; `low_priority` до приёмки качества не даёт разрешения окончательно отбросить статью. Недоступный E5, модель или несовпадающий манифест возвращают управление действующему пайплайну.

Сырые тексты, профили, человеческие метки, batch-каталоги и модельные артефакты по умолчанию находятся в игнорируемом `data/private/relevance-ml`. В репозиторий входят код, конфигурация источников и агрегированные результаты исследования.

## Эксперимент с дообучением Qwen

22 октября пользователь подтвердил доступ к GPU с 48 ГБ памяти или больше. Точная модель карты, число карт и стоимость доступа пока не указаны. Это делает эксперимент QLoRA предметным, но не подтверждает, что конкретная конфигурация уже помещается или работает. Код обучения Qwen в проекте пока отсутствует; реализованный `train` выше обучает только E5-классификатор. Новый корпус пока содержит ноль размеченных пар.

Цель первого адаптера — персональная бизнес-релевантность 0–5 с коротким проверяемым обоснованием. Дообученный Qwen может улучшить эту узкую задачу относительно исходного Qwen и GLM; фактического сравнения ещё нет. Улучшение отбора не доказывает превосходство в финансовом анализе, вопросах или проверке банковских прогнозов. Обучение на одних сырых статьях задаёт предсказание текста, а не требуемую связь новости с бизнесом.

Кандидат из текущего каталога — `Qwen/Qwen3.6-35B-A3B`. По [официальной карточке](https://huggingface.co/Qwen/Qwen3.6-35B-A3B) это 35B параметров всего и 3B активных. Арифметически 4-битные веса — порядка 17,5 ГБ, без накладных расходов, неквантованных компонентов, адаптеров и активаций. Все эксперты всё равно требуют хранения. Для GPU 48+ ГБ проверяем QLoRA с короткими полными примерами; гарантировать максимальную длину контекста до замера нельзя. Меньшие Qwen 4B/8B не включены автоматически в согласованный каталог. Явного ответа о допустимости LoRA-производной в имеющихся материалах нет; его нужно уточнить для сдачи, не объявляя такую модель заранее разрешённой или запрещённой.

Порядок работ:

1. **Зафиксировать железо и окружение.** Сохранить модель GPU, свободную VRAM, число карт, драйвер, CUDA и `torch.cuda.is_bf16_supported()`. Создать отдельное окружение обучения, закрепить версии и revision базовой модели. Не устанавливать экспериментальные пакеты в окружение работающего сайта. Если GPU арендуется, учитывать обучение и дальнейший inference в плане расходов.
2. **Заморозить независимые данные до обучения.** Выделить человеческие validation и test, суммарно ориентировочно 300–500 пар, с достаточным числом 4–5. Обычную выборку и специально подобранные критические случаи оценивать отдельно. Группы одной статьи и перепечаток целиком принадлежат одному split. Компании для проверки обобщения выделять до генерации новых пар и не включать в train. Не делить имеющиеся строки случайно: одна статья встречается у трёх компаний. Подбор промпта, порога и checkpoint использует validation; окончательный test остаётся закрытым. Отдельно проверить более свежие публикации.
3. **Снять baseline.** На одинаковых входах и доступных доказательствах проверить базовый Qwen и GLM. Зафиксировать промпт, длину контекста и режим генерации. Сравнение адаптера с тем же Qwen после 4-битной квантизации отделяет эффект обучения от эффекта смены точности. Оценку E5 сравнивать на задаче 4–5, не выдавая её за шестиклассовый ответ.
4. **Получить ответы учителя.** Использовать существующий `teacher.py`, API организаторов и общий дневной лимит 500 ₽. Первые десять пар дают оценку валидности, токенов и цены. Затем собирать 1 000–3 000 разнообразных качественных пар для первого SFT-эксперимента, продолжая к большему корпусу при необходимости. Это предлагаемый размер, не обещание качества. Проверять и исправлять ошибки, включая географию, масштаб и чрезмерную значимость. Саморазметку Qwen не считать независимым доказательством его улучшения.
5. **Экспортировать SFT.** Формат prompt/completion: вход содержит только подтверждённый профиль, новость и момент оценки; completion — проверенный ответ по контракту учителя. Сохранить grade, механизм, применимость, масштаб, географию, действие, недостающие данные и доказательства. Актуальность остаётся отдельным полем от бизнес-балла. Для старой статьи и текущего профиля явно сохранить условный характер сценария. Не включать прежние оценки во вход. Хеши, provenance и review metadata сохранять в манифесте; не обучать модель запоминать внутренние UID компаний. Loss считать по целевому ответу, а не по тексту статьи. [TRL: prompt/completion и completion-only loss](https://huggingface.co/docs/trl/en/sft_trainer).
6. **Сначала проверить короткий запуск.** Для NVIDIA GPU кандидат — 4-битная NF4-база с double quantization и LoRA; обучаются адаптеры, а базовые веса заморожены. BF16 выбирать только при поддержке картой. Начальные параметры эксперимента: rank 8–16, alpha 16–32, dropout 0,05, microbatch 1, gradient accumulation 8–16, gradient checkpointing, learning rate 5e-5…1e-4. Контекст сначала 2k–4k только для полных примеров, которые действительно помещаются; не обрезать скрыто профиль, цитаты или целевой ответ. Длинные примеры обрабатывать отдельной политикой, которую также проверяют на качестве. Сначала выполнить 50–100 optimizer steps, проверить память, конечность loss/gradients, сохранение и повторную загрузку адаптера. По измеренным токенам/сек оценить длительность, добавив evaluation и checkpoints. [PEFT: QLoRA](https://huggingface.co/docs/peft/en/developer_guides/quantization).
7. **Обучить один первый проход и выбрать checkpoint по validation.** Увеличивать число эпох или размер разметки по результату, а не автоматически. Для Qwen3.6 использовать [актуальный модельный рецепт ms-swift](https://swift.readthedocs.io/en/latest/BestPractices/Qwen3_8-Best-Practice.html), а не произвольный скрипт старого Qwen. В MoE проверить, какие модули и экспертные параметры реально получили LoRA: [PEFT описывает `target_parameters`](https://huggingface.co/docs/peft/en/developer_guides/lora). `all-linear` само по себе не доказывает охват всех экспертов. Официальный многокарточный пример — ориентир совместимости, не измеренный минимум для нашего QLoRA.
8. **Сравнить и только затем подключать.** Основные метрики — recall/precision для 4–5, число пропущенных пятёрок, ошибка балла, ошибки по географии/масштабу/отраслям, корректность цитат, валидность JSON, задержка и стоимость. Сравнить GLM, исходный Qwen и Qwen с адаптером на закрытом человеческом test. Сохранить примерный разброс оценок при малой выборке. Train loss и совпадение с teacher не доказывают превосходство над GLM. Выигравшую конфигурацию сначала подключить параллельно текущему отбору с сохранением результатов; банковский RAG и серверные проверки доказательств продолжают работать.

Для первого эксперимента не требуется размечать весь пул 29 787 пар или обучать модель финансовому анализу одновременно с отбором. Дополнение корпуса выбирается по ошибкам validation и пробелам отраслей/географии/масштаба; test не используется как очередь доразметки.

## Label Studio → обучающий датасет Qwen

Этот путь реализован в `relevance_ml/label_studio.py`: пара компании и новости становится заданием Label Studio, полный проверенный ответ человека — целевым ответом Qwen. E5 и платный API не вызываются. Предварительная разметка GLM необязательна: можно заполнить ответы вручную. Обучение адаптера на GPU запускается отдельно после подготовки датасета.

### Запуск формы

Из корня проекта:

```bash
docker compose -f compose.label-studio.yaml up -d
```

Откройте `http://localhost:8081`, создайте локальную учётную запись и проект. В Labeling Setup → Code вставьте `knowledge/label-studio/relevance-qwen.xml`. Контейнер закреплён на Label Studio 1.23.2, данные сохраняются в отдельном Docker volume; API-ключи приложения в него не передаются. Конфигурация публикует порт только на localhost. Если Label Studio запускается на удалённой машине, доступ организуется отдельно. В этой работе контейнер не запускался; XML и Docker Compose проверены без поднятия сервиса.

Готовый первый пакет из **100 реальных пар без подсказок модели**:

`data/private/relevance-ml/label-studio-qwen/batch-001-manual/`

Также подготовлен `batch-002-manual` со следующими 100 парами (`--offset 100`). Всего 200 разных задач, без предразметки и без платных вызовов. Человеческих ответов в них пока нет.

Импортируйте его `tasks.json` через Import. Снимки исходных данных и конфигурация формы закреплены рядом в `pairs.jsonl`, `label-config.xml` и `manifest.json`. Не редактируйте эти файлы после начала разметки. Для создания пакета используется команда:

```bash
PYTHONPATH=backend:backend/src:knowledge/src python -m alphich_kb.relevance_ml.label_studio export \
  --input data/private/relevance-ml/labeling-corpus-v1/pairs.jsonl \
  --output-dir data/private/relevance-ml/label-studio-qwen/batch-001-manual \
  --split train --limit 100 --offset 0
```

Готовый каталог уже существует, поэтому повтор команды откажется его перезаписывать. Для следующей партии из того же неизменного входного файла используйте новый каталог и `--offset 100`, затем 200 и так далее; размер партии — до 1000. Это выбирает следующие пары, а не снова первые 100. Перед созданием validation/test выделите независимые статьи и компании в отдельные входные файлы; один сдвиг строк не гарантирует независимость перепечаток.

### Что размечает человек

Выберите `accept` и заполните полный ответ: grade 0–5, механизм влияния, тип воздействия, точные цитаты, ID исходных фактов компании, географию, масштаб, применимость, статус события, действие, недостающие данные и отдельную оценку актуальности. Для списков подходят JSON-массивы или по одному пункту на строку. Цитату с внутренним переносом строки передавайте JSON-массивом с `\n`. Необязательные даты и действие можно оставить пустыми; отсутствие данных нельзя заменять выдуманным значением. Если пример повреждён и проверить его невозможно, выберите `unusable`: он не станет нулевой оценкой и не попадёт в обучение.

При желании `export --with-predictions` показывает уже сохранённые полные ответы учителя, если они есть во входе. Флаг не вызывает модель. Он разрешён только для train. В validation/test подсказки учителя не экспортируются. Для независимой проверки нужны два разных разметчика; одинаковый полный ответ имеет статус agreed, различающиеся ответы отправляются в `conflicts.json` без автоматического выбора победителя. В бесплатной версии можно использовать отдельные проекты для слепых проверяющих и передать оба JSON-экспорта импортёру. Различия в обоснованиях тоже требуют согласования.

### Получение SFT из человеческих ответов

После разметки выберите Export → JSON в Label Studio и сохраните файл, например, как `data/private/relevance-ml/label-studio-export.json`. Затем:

```bash
PYTHONPATH=backend:backend/src:knowledge/src python -m alphich_kb.relevance_ml.label_studio import \
  --bundle-dir data/private/relevance-ml/label-studio-qwen/batch-001-manual \
  --annotations data/private/relevance-ml/label-studio-export.json \
  --output-dir data/private/relevance-ml/qwen-reviewed/train-batch-001
```

Результаты:

- `train.jsonl` — SFT Qwen: `prompt` содержит system/user с профилем и статьёй, `completion` — проверенный JSON-ответ assistant. Вход не содержит оценки, объяснения учителя или решений проверяющего.
- `reviewed-pairs.jsonl` — исходные снимки с человеческими метками; не передаётся тренеру как текст ответа.
- `provenance.jsonl` — происхождение и отображение локальных `f1`, `f2` в исходные ID фактов. В SFT убраны технические ID компаний, статей, хеши и ссылки на внутренние исходники.
- `rejected.json`, `conflicts.json` — неполные, противоречивые или требующие согласования ответы. Не попадают в SFT.
- `manifest.json` — хеши, количества, split и формат обучения.

Импортёр проверяет неизменность компании, новости и даты, точность цитат, принадлежность фактов компании и условия оценок 4–5. Само наличие `predictions` не создаёт обучающих ответов. Отменённые, непринятые и неполные аннотации исключаются. При отсутствии пригодных ответов выходной JSONL пуст и `training_ready=false`; разметка не выдумывается. Существующие выходные каталоги не перезаписываются.

### Сборка train/validation/test для Qwen

Пакеты с `--split validation` или `--split test` экспортируются после отдельного выделения данных. Их импорт создаёт соответственно `validation.jsonl` и `test.jsonl`, а не train. На этапе сборки требуется два независимых согласованных человеческих ответа для evaluation; один человек достаточен только для обучающего примера.

```bash
PYTHONPATH=backend:backend/src:knowledge/src python -m alphich_kb.relevance_ml.label_studio assemble \
  --train data/private/relevance-ml/qwen-reviewed/train-batch-001 \
  --validation data/private/relevance-ml/qwen-reviewed/validation-batch-001 \
  --test data/private/relevance-ml/qwen-reviewed/test-batch-001 \
  --output-dir data/private/relevance-ml/qwen-sft-v1
```

В этой команде validation/test — ожидаемые будущие пакеты, их ещё нужно подготовить и разметить. Сборщик заново проверяет хеши и целевые ответы, объединяет партии и отклоняет пересечения по статьям, известным перепечаткам и точным копиям. `--company-holdout` дополнительно требует разных компаний между split. Проверка не заменяет поиск близких пересказов. Окончательные `train.jsonl`, `validation.jsonl`, `test.jsonl` читаются SFT-тренером; loss следует считать только по completion. Тексты не обрезаются конвертером: политику длины контекста и маски ответа нужно проверить на GPU до обучения. Человеческий test не добавляется в train и не используется для выбора checkpoint.
