# Автоматическая обработка новостей и локальная проверка

Runtime v11 соединяет сбор, общие факты, оценки 0–5, карточки и вопросы. Автоматизация включается явно; основной RSS-сборщик сам LLM не вызывает.

## Путь новости

1. RSS/HTML collector сохраняет статью и изолированные копии компаний. Обычный worker создаёт события.
2. Диспетчер в analysis-worker выбирает только компании из `DEMO_COMPANY_IDS`, подтверждённые collector-источники и известные даты публикации. Проверяет дешёвое тематическое основание; это предварительный отбор, не подтверждение воздействия.
3. `news_fact_extraction` запускает только извлечение и независимую проверку. Кэш фактов публичной статьи общий; привязки к source/fact ID и доступу каждой компании отдельные. Два получателя не требуют двух генераций одних фактов.
4. Для каждого профиля и роли вычисляется оценка. Ниже 4 карточка не заказывается. При 4–5 создаётся `automatic_insight`: исследователь банковских материалов → аналитик → проверяющий.
5. Перед автоматической генерацией оценка проверяется повторно. Лента публикует только 4–5 и подхватывает готовую карточку. Уточняющий вопрос использует неизменяемые профиль, дату, роль и доказательства родителя.

Решения сохраняются в `news_automation_decisions`, дневные количества заданий — в `news_automation_daily_quotas`. Повторный проход, перезапуск и две роли используют существующие задания. При изменении исходного текста/профиля/конфигурации создаётся новая версионная работа. Ошибка или неизвестная стоимость не маскируется повторным платным запросом.

Вопрос начинает с уже разрешённых банковских доказательств и не оплачивает обязательное повторное планирование поиска. При необходимости аналитик всё ещё может делегировать новый поиск. Короткий вопрос не должен запускать полный повторный разбор новости; смысловая проверка остаётся обязательной.

## Включение

Все значения задаются оператором, не LLM и не публичным HTTP-клиентом:

```dotenv
AI_AUTOMATION_ENABLED=1
AI_AUTOMATION_COMPANY_IDS=U_9250,U_99802,U_44792
AI_AUTOMATION_ROLES=cfo
AI_AUTOMATION_MAX_EXTRACTIONS=20
AI_AUTOMATION_MAX_CARDS=10
AI_AUTOMATION_SCAN_LIMIT=1000
NEWS_FEED_MAX_EVENTS=2000
```

Список компаний должен быть подмножеством `DEMO_COMPANY_IDS`, компании должны быть импортированы. Можно включить `cfo,ceo`: карточки и права ролей остаются отдельными. Максимумы считаются на UTC-день и включают созданные задания, даже если они впоследствии завершились ошибкой. Извлечение для второго tenant может использовать общий кэш и стоить ноль, но его задание тоже занимает квоту. Денежный предел — существующий общий `LLM_DAILY_LIMIT_RUB`; отдельного неучтённого бюджета у автоматики нет. Неизвестные списания сохраняют резерв. Уменьшение лимита ниже уже потраченного/зарезервированного блокирует дальнейшие вызовы.

По умолчанию `AI_AUTOMATION_ENABLED=0`. Ключ/модели и учёт стоимости должны быть настроены. В этой работе автоматизация запускалась в изолированной локальной проверке; основной `.env` не переключался на непрерывные платные вызовы.

```sh
docker compose --profile news up -d --build
# Без Docker, окружение загружается явно:
PYTHONPATH=backend:backend/src:knowledge/src python -m app.intelligence.automation status --env-file .env
PYTHONPATH=backend:backend/src:knowledge/src python -m app.intelligence.automation tick --env-file .env
PYTHONPATH=backend:backend/src:knowledge/src python -m app.intelligence.worker
```

`tick` ставит задания в очередь; выполняет их analysis-worker. Настроенный worker делает проход примерно каждые десять секунд. Текущая реализация ограничивает просмотр последними 1000 датированными RSS-событиями, возраст публикации — 90 сутками. Смена суток не создаёт повторные карточки для прежнего входа. Даты «конец дня» у HTML-источников остаются консервативными: сегодняшняя публикация с неизвестным временем ждёт завершения дня.

`GET /api/v1/companies/{id}/automation` возвращает последние 50 решений только для компании и роли текущей сессии: состояние, оценку, основания, IDs заданий. Системные задания не выдаются за задания чужой пользовательской сессии.

## Постоянный E5-индекс

`news_embedding_passages` хранит нормированные векторы с пространством модели, хэшем входа и компанией. `news_index_sources` связывает их с версиями источников и исходными координатами. Совпадение текстов разных компаний не открывает доступ к чужому кэшу. Новая версия модели получает отдельное пространство.

Фоновая индексация — бесплатный CPU-этап: idle analysis-worker индексирует по одному источнику за проход. Повторные чтения и перезапуски используют сохранённые векторы; изменение текста создаёт новые записи без сброса старых. API и карточки читают готовый кэш, не строят векторы статей при GET. Запросы компании кодируются локальным E5. Для ручного запуска:

```sh
PYTHONPATH=backend:backend/src:knowledge/src python -m app.intelligence.news_index \
  --env-file .env --company-id U_9250 --max-sources 20
```

API использует hybrid по умолчанию при готовом кэше, рассматривает до 2000 последних событий компании (настройка до 5000). Сначала фильтруются компания, источник и дата. При отсутствующих/ещё не построенных векторах используется обозначенный `lexical_fallback`, без скрытой генерации. В ответе есть `news_index`, `candidate_pool_limit` и trace режима. Это точный поиск по матрице ограниченного пула, не ANN-индекс для миллионов документов. В Compose API теперь тоже получает read-only веса E5; список компаний передаётся analysis-worker.

## Цитаты и дополнительные ограничения оценки

Extractor v17 получает `quote_units` — готовые точные фрагменты только из показанных окон исходной статьи. Модель выбирает `quote_id`, сервер подставляет исходный текст/координаты. Модельный текст в устаревшем поле `quote` при указанном ID игнорируется. Независимый reviewer проверяет именно подставленный оригинал и все атрибуты. Несуществующий ID не становится фактом. Легаси-цитаты без ID по-прежнему требуют точного уникального совпадения.

Действующее решение о ключевой ставке нормализуется в финансовый канал, не в обязанность компании. `product_scope=niche/unknown` ограничивает рыночную применимость до подтверждения ассортимента: enterprise SSD или HBM нельзя автоматически считать всем рынком компьютеров. `reference_period_end` отделяет период наблюдения от даты статьи; статистика старше 90 дней не получает 4 лишь из-за новой публикации. География регистрации не заменяет операции; суммы выручки с неизвестной единицей не используются для расчёта эффекта.

## Автономный поиск по кнопке

В аналитической ленте кнопка «Найти и разобрать 10 новых новостей» создаёт постоянное задание для выбранной компании и роли. Можно выбрать порог 4–5 либо только 5. GET/открытие страницы не запускают генерацию. Повторный клик присоединяется к активному заданию; обновление страницы восстанавливает прогресс. Другие компании и роли не видят его результаты.

Ingestion worker опрашивает десять настроенных источников, включая страницу РУССОФТ, и сохраняет статьи через существующую очередь. Это поиск по настроенным источникам и их уже собранной базе, не произвольный веб-поиск. Аналитический worker отбирает кандидатов по подтверждённому профилю, группирует перепечатки, извлекает проверенные факты и рассчитывает неизменённую оценку 0–5. Персональная карточка создаётся только после прохождения выбранного порога. Факты и подходящие готовые карточки текущей версии переиспользуются. Новый запуск исключает уже обработанные неизменённые статьи по истории компании и роли, в том числе после нового входа. Обновлённый профиль или версия источника допускают повторный отбор; незавершённые кандидаты сохраняют доступность. Пустой новый результат отделён от ранее сохранённой ленты.

Пределы: цель до 10 карточек, по умолчанию до 40 кандидатов, до 30 минут, существующий общий денежный лимит. Исчерпание источников, числа кандидатов, времени или бюджета возвращает частичный результат с причиной; оценки не повышаются ради количества. Неизвестный исход модельного запроса не повторяется автоматически. Остановка отменяет ещё не начатые модельные задания, текущий запрос завершается с учётом результата и стоимости. Фоновая массовая генерация `AI_AUTOMATION_ENABLED` при этом не включается.

API: `POST /api/v1/companies/{id}/discovery` с `Idempotency-Key` и `{target:10,min_grade:4,max_candidates:40}`; `GET` того же пути восстанавливает последний запуск; `GET /api/v1/discovery/{id}` показывает прогресс; `POST /api/v1/discovery/{id}/stop` останавливает запуск. Сохранённый анализ события доступен через `GET /api/v1/events/{id}/saved-insight`, даже если оно не вошло в текущую короткую ленту.

## Анализ компании

Раздел «Анализ компании» читает `GET /api/v1/companies/{id}/business-context` без модельных вызовов. Он показывает признаки выбранного юрлица, условные бизнес-гипотезы, механизм влияния, необходимые данные и решение, которое от них зависит. Поддержаны строительство, ИТ, торговля, транспорт и производство. Регистрация не подтверждает операции; GROUP_ID не наследует чужой долг; платёжный поток не устанавливает роль контрагента. Исходная выручка остаётся в исходных единицах. Рыночная доля и денежный эффект без подтверждённых исходных данных не рассчитываются.

Тот же контекст передаётся аналитическому агенту как необязательные примеры, а не закрытый перечень последствий. Аналитик выбирает применимое влияние из события и подтверждённой связи с компанией: репутационное, правовое, кадровое, технологическое, операционное, связанное с безопасностью, экологией, клиентами, партнёрами, финансами или другой темой. Денежный эффект не обязателен. Сервер не выбирает канал по финансовому словарю и не скрывает признаки банковских продуктов; их наличие по-прежнему не доказывает остатки и условия договора. Допустимы до двух независимо обоснованных выводов, без требования заполнять лимит. Каждый опирается на первичный факт текущего события и содержательный признак компании; ОКВЭД не является единственным допустимым основанием.

Извлечение и проверка фактов поддерживают открытые темы `topics` и `business_effect`, ограниченные форматом и размером. Репутационный инцидент или нарушение безопасности не отбрасывается из-за отсутствия экономической темы. Сообщение об обвинении или расследовании не становится доказательством виновности, а чужой инцидент — собственным инцидентом компании. Роли CFO/CEO задают приоритет решения, не ограничивая предмет анализа финансовыми показателями.

Банковский RAG ищет свободный запрос по всему разрешённому корпусу, включая нефинансовые темы. `metric` — необязательный точный фильтр, а не условие наличия результата. Проверенный качественный тезис может иметь свободный `topic` и `metric=null`; источник, автор, дата, статус проверки и горизонт сохраняются. Для качественных тезисов пересмотр задаётся явно через `revision_of`, чтобы новая позиция о безопасности не скрывала независимую позицию о репутации. Непроверенный OCR и чужая цитата не объявляются мнением банка. Семантически найденные страницы и пригодные проверенные тезисы остаются разными результатами поиска; отсутствие подходящей позиции — допустимый результат.

Отбор готовых проверенных тезисов по свободному запросу пока лексический, по самому утверждению и проверенной цитате; семантический поиск страниц сохраняется. Для прогноза требуется явно заданный горизонт. Новый код не добавляет отсутствующие позиции в PDF или реестр: существующий индекс нужно отдельно обогатить проверенными тезисами, когда такие источники есть.

`GET /api/v1/insights/{id}/quality` возвращает бесплатную диагностику структуры цитат и связи действий с выводами. Она не оценивает истинность причинности: `semantic_correctness` и `business_usefulness` остаются `null`, независимая человеческая проверка отмечается как отсутствующая. Сохранённые карточки прежней методики имеют `analysis_method_current=false`; интерфейс предлагает явную повторную проверку вместо скрытой платной генерации.

При обновлении контейнера analysis-worker завершает текущее задание перед выходом по SIGTERM. Период остановки позволяет дождаться ограниченного числа модельных вызовов; существующие неизвестные резервы этим не освобождаются.

## Контрольные примеры и живой прогон

`knowledge/fixtures/real_news_selection_labels.v3.json`: 12 дополнительных настоящих статей, 36 оценок для тех же трёх компаний, шесть положительных пар. Вместе с v2: 62 новости, 186 пар, девять положительных. Новые источники не пересекаются с 50 источниками v2. Включены прогноз спроса на ноутбуки, решение ЦБ, ипотека, узкие серверные категории, отчёт за прошлый год и локальные рынки. Это предварительная разметка агента и набор разработки, не независимый benchmark.

Для локального сквозного прогона есть отдельный runner. По умолчанию он **не генерирует**: создаёт новую изолированную SQLite, воспроизводит замороженные тексты через RSS/ingestion worker и строит бесплатный E5-индекс. Исходные тексты имеют реальное происхождение, но discovery-feed в этом тесте контролируемый, а доступность внешних сайтов проверяется отдельно. Полные данные/отчёты остаются в игнорируемом `data/processed`, файлы БД и отчёта приватные.

```sh
PYTHONPATH=backend:backend/src:knowledge/src python -m app.intelligence.acceptance \
  --env-file .env \
  --profiles data/processed/selection-real-news-v2/profiles.json \
  --events data/processed/selection-positive-v3/live-events.json \
  --max-articles 6 --max-cards 2 --budget-rub 2 \
  --output data/processed/ai-acceptance.local.json
# Генерация включается только явным --live.
```

Для повторного уточняющего вопроса есть `--resume-report <старый отчёт> --live`: используется исходная БД и исходный денежный предел, предыдущий отказ сохраняется. Повтор того же вопроса не создаёт новые расходы даже при новой demo-сессии. Это не сброс журнала и не освобождение неизвестных резервов.

Результат локальной работы 21.10.2026:

- E5: 18 привязок исходных статей, веса и банковский индекс загрузились локально.
- Мост платёжных контекстов проверен для трёх компаний: по два признака, владельцы и версии соответствуют профилям. Сохранённая карточка и ответ повторно прошли read-only структурный аудит: 2/2, без генерации.
- Реальная новость о рынке ноутбуков прошла до карточки 4/5, с банковским тезисом и отдельной смысловой проверкой.
- Первый уточняющий ответ verifier отклонил. После исправления режима вопроса другой уточняющий вопрос успешно прошёл; доказательства открыты через API. Отказ не заменялся фиктивным успехом.
- В v17 новость Минтранса прошла извлечение по ID, независимую проверку и получила 5. В этом контрольном запуске новая карточка не генерировалась из-за исчерпанной квоты карточек теста; проверено состояние `awaiting_card_quota`.
- 25 реальных модельных вызовов вместе с исправлениями: **1,873286 ₽** по квитанциям, неизвестных резервов 0, исходный локальный предел 2 ₽ не обнулялся.

Локальные артефакты: `ai-acceptance-preflight.local.json`, `ai-acceptance-live-v15.local.json` (первый запуск с найденными дефектами), `ai-acceptance-followup-v16.local.json` (успешный вопрос), `ai-source-units-live-v17.local.json` (точная цитата/оценка 5), `ai-local-readiness.local.json`. Всё под `data/processed`.

Это функциональная проверка выбранных реальных сценариев, не доказательство качества всей новой разметки. На всей матрице 186 пар текущий extractor v17 платно не запускался. На общем сервере тест не проводился — сервер ещё не поднят; локальный Docker daemon также не запущен. API/БД/очереди проверялись через настоящий FastAPI TestClient/SQLite и разрешённый шлюз.
