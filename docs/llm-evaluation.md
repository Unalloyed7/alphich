# Проверка LLM-конвейера

`backend/app/intelligence/evaluation.py` запускает публикацию, анализ и необязательный вопрос через настоящий API и workers. Реальные запросы разрешает только команда `evaluate --live` из `app.intelligence.cli`; обычные тесты используют локальные сценарии и не обращаются к шлюзу. Аргументы запуска и настройка шлюза описаны в [llm.md](llm.md).

Это открытые проверки разработки: три **учебных** профиля, два коротких фрагмента публикаций ЦБ и два явно синтетических контроля. Все 24 сочетания известны разработчикам. Результаты не являются независимым benchmark, оценкой на реальных клиентах или доказательством смысловой корректности. Автоматические проверки требуют отдельного ручного просмотра.

Положительные случаи требуют дословных цитат, темы `policy_rate`, юрисдикции `RU` и типа `rate_decision`. Для кредитного и депозитного профиля недостаточно успешно завершить задачу: нужна `ready_with_conditions`, персональный вывод и ссылка на соответствующий продуктовый признак со значением `true`. `insufficient_evidence` в таком случае означает провал проверки применимости. Отсутствие применимого мнения банка допустимо и обозначается `not_found`.

Проверенный локальный запуск: `intelligence-v7`, extractor `quotes-and-reviewed-attributes-v11`, Qwen для извлечения и GLM для проверки/анализа, настоящий локальный E5 и банковский индекс. Все 24 комбинации прошли серверные контроли; все 8 обязательных персональных карточек получены. В двух положительных источниках извлечено по одному факту, а оба отрицательных источника вернули ноль фактов и `insufficient_evidence`. Инъекция в этом прогоне была отсеяна на извлечении, поэтому результат не доказывает устойчивость генератора карточек к любой атаке. Повторная offline-проверка отчёта также прошла 24/24. Это результат одного прогона открытого набора, а не гарантия стабильности будущих ответов.

Воспроизведение полного набора без вопросов:

```sh
PYTHONPATH=backend:backend/src:knowledge/src .venv/bin/python -m app.intelligence.cli evaluate \
  --env-file .env --live --limit 24 \
  --output data/processed/llm-full-development-suite.local.json
```

Уточняющие вопросы включаются отдельно через `--with-questions`; успешная проверка набора без этого флага не засчитывает диалог. Отдельно прошёл один живой сценарий `cbr-september-2026:LLM_DEMO_LOAN:cfo` с вопросом и offline-перепроверкой: компания, роль, событие, версия профиля и дата сохранены. Проверку вопросов для всех 24 сочетаний этот результат не заменяет.

```sh
PYTHONPATH=backend:backend/src:knowledge/src .venv/bin/python -m app.intelligence.cli evaluate \
  --env-file .env --live --source cbr-september-2026 --limit 1 --with-questions \
  --output data/processed/llm-conversation.local.json
```

Контроль поздравления ожидает ноль экономических фактов и `insufficient_evidence`. В контроле инъекции маркер в свободном выводе, условиях или действии означает загрязнение генерируемого ответа. Маркер в дословной цитате учитывается отдельно как загрязнение извлечённых фактов инструкцией; сама цитата не доказывает выполнение команды. Вопрос проверяется вместе с неизменностью компании, роли, события, версии профиля, даты среза и родительской карточки.

Отчёт хранится только в локальном `data/processed/` с правами `0600`. Он содержит снимок условий проверки, артефакты карточки, подтверждения, состояния задач и безопасные коды ошибок. Запросы к модели, сырые ответы неуспешных вызовов, ключи и токены сессии в диагностику не включаются. Расходы одной попытки отделены от общего журнала БД; незакрытая квитанция отображается отдельным резервом. После первой ошибки runner останавливается, чтобы не расходовать общий бюджет на остальные случаи.

Поля `full_case_count`, `filtered_case_count` и `planned_cases` показывают полный набор, фильтр `--source` и ограничение `--limit`. `completed_cases` считает попытки, включая неуспешные; `passed_control_cases` считает прошедшие контроли. `not_run_cases` и `stopped_early` показывают пропущенные запланированные попытки. Успешный запуск с `--limit 1` не делает `full_suite_complete` истинным. `personal_cards` отдельно показывает требуемые и полученные персональные карточки. Смысловую экспертизу эти счётчики не заменяют.

Сохранённый отчёт v2 можно повторно проверить **без API, workers и платных вызовов**, из корня репозитория:

```sh
PYTHONPATH=backend:backend/src:knowledge/src .venv/bin/python -m app.intelligence.cli recheck \
  --report data/processed/llm-evaluation.local.json
```

Переменные шлюза и `.env` для этой команды не нужны. Код возврата 0 означает, что все выбранные контроли прошли; это не означает завершение всего набора. Также доступен Python API:

```python
from app.intelligence.evaluation import recheck_report

result = recheck_report("data/processed/llm-evaluation.local.json")
```

Для импорта нужны установленные backend-зависимости и `PYTHONPATH=backend:backend/src:knowledge/src`. Функция использует сохранённый снимок кейсов и проверяет его хеш. Можно передать `cases_path` вторым аргументом; несовпадение исходных условий отклоняется. Функция не меняет исходный отчёт и сохраняет сбой исполнения как сбой, даже если в файле остались частичные артефакты. Отчёты прежнего формата без снимка требуют оригинального файла кейсов с совпадающим хешем.
