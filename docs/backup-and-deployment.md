# Alphich: локальный backup и подготовка к VPS

Текущий стек использует PostgreSQL 16.8 внутри `docker compose` с постоянным volume `pgdata`.
Backup делается из **запущенного** `postgres` командой `pg_dump -Fc`: согласованный снимок
сохраняется без остановки RSS и API. Копирование файлов живого Docker volume вместо dump
**не подходит**.

## На Mac: сделать архив и проверить восстановление

В корне репозитория (Docker Desktop запущен, PostgreSQL healthy):

```bash
bash scripts/backup-postgres.sh
# Возьмите путь из строки BACKUP_OK; пример:
bash scripts/verify-postgres-backup.sh backups/alphich-postgres-YYYYMMDDTHHMMSSZ-NNNN.dump --require-insight
```

Файлы `backups/*.dump` и `*.sha256` **не публиковать и не коммитить**. Архив включает
не только демоданные, но и журналы вызовов, AI-ответы и активные хеши демосессий.
Скрипт создаёт архив с правами 600, checksum SHA-256, а затем второй скрипт восстанавливает
архив в отдельном одноразовом контейнере PostgreSQL **без сети и без портов**.
Он проверяет таблицы `companies`, `events`, `source_documents`, `insights`,
`insight_answers`; флаг `--require-insight` запрещает считать успехом пустой набор инсайтов.
Это проверяет пригодность дампа, но не заменяет E2E браузерную приёмку.

При изменении данных после этого шага создайте **новый** архив перед окончательным переносом.

## Отдельно от БД сохранить объекты с Mac

Проверьте наличие модели и индекса до заказа VPS:

```bash
du -sh data/models/e5-base data/processed/bank-index-v1
find data/models/e5-base -type f | head
find data/processed/bank-index-v1 -type f | head
```

Оба каталога игнорируются Git и не входят в PostgreSQL. Веса, индекс и содержимое `.env`
передаются на VPS отдельно по SSH; секреты не вставляются в issue, PR, чаты или логи.

## Порядок восстановления на *новом* VPS

1. Проверить бесплатно доступные ресурсы и условия оплаты; **не создавать платные ресурсы** без подтверждения бюджета.
2. При выборе VPS: Ubuntu 24.04 x86_64, от 4 vCPU / 8 GiB RAM / 60+ GiB SSD,
   публичный IPv4. Docker Engine + Compose plugin. Секретный `.env` задаётся до первого запуска PostgreSQL.
3. Перенести код, архив БД, E5 и индекс защищённым каналом. Назначить приватные права файлов.
4. Запустить **только** базу: `docker compose up -d postgres`.
5. Восстановить dump **только в новую пустую БД до первого запуска API**. Пример после размещения дампа в `/tmp/alphich-backup.dump` внутри контейнера:

   ```bash
   docker compose cp /private/path/to/backup.dump postgres:/tmp/alphich-backup.dump
   docker compose exec -T postgres sh -eu -c 'exec pg_restore --exit-on-error --no-owner --no-privileges -U "$POSTGRES_USER" -d "$POSTGRES_DB" /tmp/alphich-backup.dump'
   docker compose exec -T postgres rm /tmp/alphich-backup.dump
   ```

   **Не выполняйте эту процедуру на Mac или на работающей/непустой БД**: это только для вновь созданного пустого VPS-тома, где таблицы приложения ещё не созданы.
6. Проверить `DEMO_COMPANY_IDS`, затем стартовать приложение:

   ```bash
   docker compose --profile news up -d --build
   docker compose --profile news ps
   python3 scripts/verify-stack.py
   python3 scripts/verify-personas.py --require-insight
   ```

7. Защитить всю публичную поверхность (включая `/api/`) HTTPS + Basic Auth на reverse proxy.
   Внешние порты: 80/443 и ограниченный SSH; 5432, 8000, 5173 не открывать наружу.
   RSS и анализу нужен исходящий интернет. Учесть работу сертификатов и DNS.
8. Проверить две компании × две роли, реальные RSS, чтение источников/evidence,
   сохранённые ответы, перезапуск контейнеров и потребление ресурсов. Не выполнять платные
   LLM-анализы без явного разрешения и контроля бюджета.
9. Для резервного локального запуска хранить отдельную копию рабочего дампа на Mac.
   По завершении демо проверить удаление сервера, дисков и публичных IP, а также счета хостинга.

### Платёжные связи (отдельная backend-задача)

Контракт для backend-коллеги: только наблюдаемые направленные платежи между анонимными ID.
Вычислять агрегаты по отправителю/получателю, суммы, количество и доли при известных единицах;
долю от исходящего / входящего **наблюдаемого** объёма с явно указанным знаменателем.
Считать концентрацию, сохраняя происхождение из CSV, информацию о пропусках и покрытии.
Не выводить назначение платежа, период, коммерческую роль контрагента и причинную связь,
если их нет в источнике. Не показывать реальные финансовые связи вне границ разрешённой
демокомпании. Frontend подключаем только после согласования API схемы, units и ограничений.
