# Отбор новостей под компанию

`alphich_kb.personalization.selector.NewsSelector` принимает профиль и версии публикаций, возвращает до пяти событий с основаниями, очередь извлечения фактов и вопросы для банковского RAG. Модуль работает отдельно от API и не вызывает генеративную LLM. Отсутствие подходящего PDF не влияет на отбор новости.

Одна новость о ставке даёт разные основания: кредитный продукт — условия финансирования, депозит — условия размещения средств, отсутствие обоих подтверждённых продуктов — общий денежно-кредитный контекст. Признак продукта не сообщает остатки, тип ставки или условия договора; эти ограничения сохраняются в результате.

## Быстрый запуск

Из корня репозитория, без загрузки модели и без сторонних пакетов:

```sh
PYTHONPATH=knowledge/src python3 -m alphich_kb select-news \
  --company-id S_BUILD --as-of 2026-10-20T12:00:00Z --mode lexical
```

По умолчанию используются **вымышленные** компании и публикации из `knowledge/fixtures/`. Они проверяют поведение программы; это не сообщения о реальных событиях. URL `example.invalid` не загружаются. Для сравнения смените компанию на `S_RENT`, `S_SOFTWARE`, `S_FAB` или `S_GRAIN`.

Для локальной E5 установите зависимости и скачайте закреплённую модель по [инструкции RAG](rag.md). Затем:

```sh
PYTHONPATH=knowledge/src knowledge/.venv/bin/python -m alphich_kb select-news \
  --company-id S_RENT --as-of 2026-10-20T12:00:00Z \
  --bank-index-dir data/processed/bank-index-v1 \
  --bank-event-id rate_decision
```

Поиск новостей по умолчанию `hybrid`, банковских материалов — `dense`. Вторая команда добавляет `bank_contexts` для первого выбранного события с подтверждённой применимостью или явно заданного `--bank-event-id`. Это подготовка контекста, а не готовая карточка. Режим `--mode lexical` использует только текстовый поиск в обоих контурах. Операционная недоступность E5 явно помечается `lexical_fallback`; повреждённые данные и несовместимые версии не маскируются fallback.

Свои данные передавайте через `--profiles` и `--events`: поддерживаются JSONL, JSON-массивы и объекты с массивами `companies`/`events`. Для единственного профиля допустим отдельный JSON-объект. Нужны исходные feature IDs и полные тексты источников. Выход `contexts.jsonl` из ETL подходит напрямую.

## Подключение в worker

```python
from alphich_kb.embeddings import E5Encoder
from alphich_kb.personalization.inputs import SelectionScope, from_backend_event
from alphich_kb.personalization.selector import NewsSelector

encoder = E5Encoder(model_dir="data/models/e5-base")

# event_dtos и source_dtos_by_event загружены сервером с проверкой владельца.
events = [from_backend_event(e, source_dtos_by_event[e["id"]]) for e in event_dtos]
selector = NewsSelector(events, encoder)  # Один снимок пула для многих компаний.

# Все значения scope берём из проверенной серверной задачи.
scope = SelectionScope(
    company_id=job_company_id,
    as_of=job_as_of,
    allowed_event_ids=frozenset(authorized_event_ids),
    role=job_role,
)
result = selector.select(company_profile, scope, limit=5, mode="hybrid")
```

В lexical режиме encoder можно не создавать. Для установки пакета в окружение backend: `pip install -e 'knowledge[retrieval]'`; воспроизводимые версии находятся в `knowledge/requirements-rag.lock`.

Адаптер поддерживает два существующих формата компании: ETL `contexts.jsonl` и DTO профиля API. Он проверяет принадлежность feature компании, версию и соответствие значению профиля. При отсутствии доказательства продукта прямое основание не создаётся. Метаданных `GET /events/{id}` недостаточно: нужны авторизованные тела `GET /sources/{id}`. Сам адаптер HTTP-запросов не делает. Фактические маршруты и очередь подключает backend; этот пакет их не регистрирует.

E5 кодирует ограниченные фрагменты публикаций один раз при создании `NewsSelector`, затем переиспользует их для всех компаний этого снимка. Одинаковые подготовленные тексты делят вектор. Записи `embedding_records` сохраняют источник, версию, точный span, hash входа и embedding space. В этой реализации матрица хранится в памяти; постоянного инкрементального индекса новостей ещё нет. При новом пуле создайте новый selector. На большом потоке следующим шагом будет хранение и обновление этих записей в backend.

## Формат события и доверие к фактам

Входной снимок содержит `id`, `version`, `company_id` (`null` для общего источника), `title`, `published_at`, необязательный `event_at`, `sources` и `facts`. Каждый источник имеет `id`, `version`, `text` и подтверждённое сервером время доступности `available_at` либо `received_at`.

Факт — серверная аннотация, закреплённая за источником:

```json
{
  "id": "server_issued_immutable_fact_id",
  "text": "Точная выдержка из публикации",
  "source_id": "source_id",
  "source_version": "1",
  "source_span": {"start": 0, "end": 29},
  "source_available_at": "2026-10-19T10:01:00Z",
  "verification_status": "verified",
  "attributes": {
    "topics": ["policy_rate"],
    "industry_codes": [],
    "countries": [],
    "regions": [],
    "geography": "RU",
    "kind": "rate_decision"
  }
}
```

`text` обязан совпасть с `source.text[start:end]`. Смещения измеряются в Unicode code points Python. Модуль проверяет точную цитату, версию, временную доступность и структуру атрибутов. Неверная аннотация исключается и учитывается в `rejected_fact_count`. Противоречащие снимки с одинаковым ID/версией отклоняются.

**Совпадение цитаты не проверяет истинность классификации.** Статус `verified` и атрибуты принимает только доверенный серверный этап проверки; клиент и LLM не могут назначать их самостоятельно. Политика этой проверки и генеративное извлечение остаются задачей backend/агента. В fixtures `human_verified` относится только к вымышленному сценарию.

Пустой `facts` допустим: словарные упоминания создают `needs_extraction`, ссылки на исходные spans и пустой `matched_fact_ids`. `extraction_candidates` содержит до трёх таких кандидатов независимо от пяти мест ленты. После извлечения сервер создаёт новую версию события, и отбор выполняется повторно. Смысловой матч без структурного основания попадает только в `review_queue`, а не получает подтверждённую применимость.

## Правила отбора

Для компании создаются до семи запросов: отрасль, подтверждённые финансовые продукты, торговые страны, регион регистрации, известные отрасли платёжных соседей, роль и макроконтекст. Отрицательные и неизвестные продукты не становятся поисковыми словами. Словарь отраслей небольшой и версионируемый; он не покрывает весь ОКВЭД.

До top-15 в каждой ветке исключаются чужие события, неизвестное время доступности, будущие публикации и версии. Затем берётся последняя допустимая версия события. Будущая дата вступления закона в силу не исключает уже доступную новость о нём. Доступ применяется и к вложенным источникам; `company_id` частной публикации должен совпадать с компанией задачи. Обновление старой публикации не обнуляет её возраст.

SQLite FTS5 даёт lexical кандидатов, E5 — dense кандидатов. Фрагменты сворачиваются до события, ранги объединяются через RRF с `k=60`. Между запросами берётся максимум нормированного ранга. Совпадения многих фасетов не складываются в неограниченный бонус. Структурные правила проверяют весь допустимый пул, поэтому важное подтверждённое событие может пройти и вне top-15 retrieval.

| Основание | Что можно утверждать |
| --- | --- |
| Российская ставка + подтверждённый кредит/депозит | Тема условий финансирования/размещения; денежный эффект и договор неизвестны |
| Область события совпадает с ОКВЭД | Тематическая применимость в `RU`/`GLOBAL`; иностранная операционная география требует проверки |
| Страна ФТС + торговое изменение | Условный торговый контекст; при указанной отрасли она также должна совпасть |
| Регион регистрации | Региональный контекст, без предположения о расположении объектов |
| Отрасль платёжного соседа | Контекст связи: доля полного потока и отдельно охват профилями; смысл платежей неизвестен |
| Одно смысловое совпадение | Кандидат на дополнительную проверку |

Доля платёжной отрасли уже рассчитана от полного потока. Она не перенормируется по известным контрагентам и не умножается повторно на охват. Поддерживается только метод ETL `nonself_all_flow_denominator_normalized_duplicates_once`.

`priority` — внутренняя шкала сортировки 0–100: сильнейшее основание плюс свежесть (до 5), ранг поиска (до 4) и интерес роли (до 4), с ограничением 100. Это не вероятность, размер ущерба или экспертно откалиброванная значимость. По умолчанию в ленте до двух событий одной темы; подтверждённое решение ЦБ может пройти сверх этого ограничения. Перепечатки с одинаковыми заголовком, текстом и датами занимают одно место. Семантическое объединение разных публикаций пока не реализовано.

## Результат и банковский RAG

В `items` входят событие/версия, статус, приоритет, причины с пояснениями, реальные `matched_feature_ids`/`matched_fact_ids`, охват, ограничения, ранги и до двух `bank_questions`. `relevance_tier` различает `direct`, `context`, `hypothesis`; статус `applicable_with_conditions` означает основание применимости темы, а не готовность персональной аналитической карточки.

У вопроса есть `query`, `metric`, `horizon`, `as_of` и ID оснований. Горизонт прогноза берётся из проверенного факта; без него используется конец года анализа как параметр поиска. Это не извлечённый прогноз банка. Для PDF известен только день публикации, поэтому автоматически используется последний завершённый день UTC (`completed_utc_day`), без предположения о времени выхода сегодняшнего обзора.

Сервер передаёт вопросы в `BankRetriever` с отдельным разрешённым набором банковских документов, затем использует `context_for_model`. Статусы банка `found`/`historical_only`/`conflicting`/`not_found` принадлежат этому второму этапу. При `not_found` новость остаётся выбранной; модель должна явно обозначить отсутствие банковской оценки. Интеграционная CLI получает банковский контекст только для события `applicable_with_conditions`.

`trace` содержит версии профиля/метода, допустимые снимки, счётчики исключений, режим, выбранные ID и время. Он не содержит заголовки исключённых чужих публикаций. Scope в Python API обязателен. В локальной CLI по умолчанию разрешены все записи переданного файла/банковского индекса; флаги `--allow-event` и `--allow-bank-document` сужают набор. Это удобство локального запуска не заменяет авторизацию приложения.

## Проверка и ограничения оценки

```sh
PYTHONPATH=knowledge/src knowledge/.venv/bin/python -m unittest discover -s knowledge/tests -v

PYTHONPATH=knowledge/src knowledge/.venv/bin/python -m alphich_kb compare-news
```

`knowledge/fixtures/relevance_labels.json` содержит 150 явно размеченных пар: пять вымышленных компаний × 30 событий; 31 снимок включает обновление из будущего. Генератор fixtures не выводит оценки из предсказаний selector. Шкала 0–3 описывает тематическую применимость, а не финансовую экспозицию. Проверяются также доступ, даты, ложное совпадение страны, отсутствующие факты, перепечатки и разные интересы кредитного/депозитного клиента.

В сохранённом [отчёте](../knowledge/news_selection_report.json) средний nDCG@5 равен **0,9619** во всех трёх режимах; в top-5 нет пар с оценкой 0. Ограничение разнообразия снижает выдачу повторных отраслевых регуляторных событий для разработчика ПО. Это открытый набор разработки, созданный вместе с правилами: он не доказывает качество на реальных новостях и не показывает выигрыша E5. Время в отчёте измерено на локальном прогретом worker, без генерации и построения новостных векторов; это не оценка хостинга.

Модуль подключён к [LLM worker и API feed](llm.md). Извлечение, агент и проверка карточки тестируются на HTTP-заглушке до получения доступа к шлюзу. Следующий рубеж — новая реальная публикация через разрешённую модель и отдельный набор размеченных реальных пар, который не используется при настройке правил.

## Обновление бесплатного этапа

Выборщик v2 группирует близкие перепечатки после фильтров доступа/времени, сохраняет источники группы и защищает числовые изменения. Платёжные контексты можно привязать к профилю API через проверяемый адаптер. На 24 настоящих RSS-статьях выполнено локальное сравнение трёх методов; разметка предварительная, не независимая. [Контракты, команды и ограничения](ai-offline.md).

## Производственная лента 4–5

Выборщик v3 возвращает оценку по [новой шкале](news-grading-v2.md). Для финальной ленты вызывайте `select(..., min_grade=4)`; HTTP `/api/v1/companies/{id}/feed` уже делает это. `min_grade=0` по умолчанию оставлен для совместимости локального поиска кандидатов и ручного анализа, это не порог производственной ленты. Нижние оценки не заполняют свободные места в top-5. `extraction_candidates` сохраняются отдельно даже при пустой финальной ленте. Локальные и тематические совпадения не превращаются в значимый бизнес-фактор от высокого cosine/RRF.

Официальность — характеристика происхождения, не гарантия истинности или релевантности. Встречи, поздравления, локальные пилоты и релизы не повышаются до 4 от домена ведомства. CNews и Elec.ru сохранены в отдельном `backend/app/rss_sources_extended.json`: они могут быть полезны для отдельных компаний, но продуктовые пресс-релизы исключены из стандартного потока. Это альтернативный операторский конфиг, не автоматическое объединение с основным.

Минстрой, ДОМ.РФ, Минцифры, Росстат и ФАС проверялись как кандидаты; из текущей среды получены ошибки соединения/403, поэтому в автоматический конфиг не добавлены. Нет случайно подобранных RSS URL или обхода ограничений.

Для трёх HTML-лент используются фиксированные селекторы конкретных просмотренных страниц. Пустая/изменившаяся вёрстка даёт `listing_layout_changed_or_empty`, а не успешный пустой результат. Каждая ссылка и редирект проходят существующий allowlist/DNS/IP/размер/таймаут; статья загружается полностью один раз, затем используются изолированные копии компаний. При формате даты «день» фиксируется конец дня в часовом поясе издателя (Минтранс/ЕЭК UTC+3, TrendForce UTC+8); до его окончания материал не попадает в исторический отбор. Дата не выводится из URL и не подменяется временем загрузки.

Сборщик сам не запускает платный анализ. Отдельный [диспетчер AI](ai-pipeline.md) в analysis-worker может автоматически поставить извлечение и карточки 4–5; включается `AI_AUTOMATION_ENABLED=1`, по умолчанию выключен. Добавлены постоянные векторы E5 в БД, hybrid-лента по пулу до 2000 событий и обозначенный fallback при неготовом индексе. Старые сведения выше про лексический API и отсутствие постоянного новостного индекса описывают прежний этап.
