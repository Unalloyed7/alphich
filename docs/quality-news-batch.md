# Quality Lab — пакетная подготовка первоисточников (PR: news snapshots)

**Статус:** отдельный offline-by-default инструмент для локального Mac. Не меняет базу Quality Lab, продовый Postgres, `discovery.py`, модель ML или промпты. Не вызывает LLM и не расходует AI-бюджет. Сетевой доступ к публичным оригиналам требуется только при явной команде `fetch --fetch`.

## Цель и порядок

Исходные фикстуры `real_news_selection_labels.v2.json` и `.v3.json` содержат 62 ссылки и 186 пар, но не полные тексты статей. Локальная база Quality Lab уже умеет принимать отдельно подготовленный `{event_id: {text,published_at}}`. Этот скрипт автоматизирует скачивание оригинальных текстов и даёт эксперту возможность подтвердить их **до** импорта.

1. `fetch`: явный ограниченный запрос к ранее известным публичным URL. Использует **существующие** `app.rss_fetch.PublicFetcher` (allowlist/SSRF check, лимиты, редиректы) и `app.rss_parse.article_text`, `article_publication_date` (trafilatura и HTML metadata). Сетевые ошибки фиксируются, но не подменяются фиктивными статьями.
2. В приватном каталоге создаётся `preview.html` со всеми **непроверенными** текстами; оператор сверяет ссылку, заголовок, полноту, дату и принадлежность источника, отмечает несоответствия. Статьи в `draft_articles.json` **не являются** human gold.
3. `approve`: оператор **явно** перечисляет ID проверенных статей. Программа подтверждает неизменность текста по SHA-256 и создаёт `review_articles_APPROVED.json`; молчаливого одобрения всех записей нет.
4. `quality_review.py enrich`: существующий инструмент вносит подтверждённые статьи в **локальную** базу. После первой человеческой оценки enrichment запрещён; в таком случае создайте новую базу, не изменяйте уже использованный benchmark.

## Установка и пробный запуск на Mac

Из корня репозитория. Если локальное Python-окружение backend уже установлено — используйте его. Иначе (Python 3.12+):

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
```

Скачайте небольшой пакет **v3** (первые пять оригинальных статей из v3). Команда ничего не запускает в Docker и не обращается к AI-шлюзу:

```bash
.venv/bin/python scripts/quality_news_batch.py fetch \
  --dataset v3 --batch v3-first-5 --limit 5 --delay 1.0 --fetch
```

`--fetch` обязателен: его отсутствие предотвращает неумышленную загрузку. По умолчанию 5 URL, пауза между запросами не менее 0.5 секунды, допустимо не более 62 ссылок на один запуск. Каждый ID batch должен быть новым; старые файлы не перезаписываются. В `data/private/quality-news/v3-first-5/` появятся:

| Файл | Что в нём |
|---|---|
| `manifest.json` | SHA256 фикстуры, URL, результат, контрольные суммы, время загрузки, ошибки и отсутствие подтверждения |
| `draft_articles.json` | event ID → текст и **только явно извлечённая HTML-дата**, либо null |
| `preview.html` | Локальный просмотр черновиков со ссылками на оригиналы; текст экранирован как текст |

Откройте в Finder или командой:

```bash
open data/private/quality-news/v3-first-5/preview.html
```

Сверьте оригиналы. Если статья оказалась неполной/поменялась, оставьте её неподтверждённой и соберите корректный текст вручную с источником/версией. Нельзя молча принимать только первые абзацы или подменять старую новость свежей. `published_at=null` означает, что метаданные статьи не позволили подтвердить дату; не угадывайте её по URL. Утверждённые вручную даты при необходимости готовятся как отдельная документированная процедура.

Для каждой сверенной статьи найдите `event_id` в `manifest.json` и одобрите **только эти ID**:

```bash
.venv/bin/python scripts/quality_news_batch.py approve \
  --batch v3-first-5 --ids v3_10c7f12ca7da0e47d9c1
```

После этого при условии, что человеческих оценок пока нет:

```bash
python3 scripts/quality_review.py enrich \
  --db data/private/quality-review.sqlite3 \
  --articles data/private/quality-news/v3-first-5/review_articles_APPROVED.json
```

Если одобрен только один event ID, получите обновление **трёх пар** (для трёх компаний), а не пяти. Если этот event ID уже был загружен вручную, enrichment обновит тот же текст — сперва сравните его со старым, чтобы не потерять более качественный снимок. При отсутствии необходимости повторно загружать уже имеющуюся статью просто не включайте её в `approve`.

## Ограничения и безопасность

- Используем только HTTPS и **закреплённый набор хостов из текущих v2/v3**. Редиректы на другой хост не принимаются, даже если у домена есть алиас: такую неудачу можно проверить вручную, не ослабляя SSRF-ограничения.
- Запросы ограничены по байтам и времени существующим публичным fetcher. Серверы могут отвечать 403, 429, таймаутом или блокировать ботов. Это отражается как `failed`, а не как отсутствие новости. Скрипт не обходит ограничения сайтов.
- Внешние новости могут содержать ошибки и инструкции к AI; эти данные никогда не обрабатываются как команды. `preview.html` экранирует HTML. Не открывайте произвольные ссылки, не сверив домен.
- `manifest.json` доказывает происхождение локального снимка, **не истинность факта в мире**. HTML `article:published_time` — это указание источника, а не независимая проверка экспертом.
- Два источника с близким заголовком не обязательно одна статья; дедупликацию/группировку перепечаток и версии корпуса ведёт `scripts/relevance_dataset.py` при экспорте и отдельный процесс человеческой проверки.
- Не коммитьте `data/private/`, `preview.html`, исходные профили компаний или тексты статей в публичный GitHub. `.gitignore` уже исключает `data/private/`.
- Для полноценного обучения всё ещё потребуются человеческие оценки и больше положительных сочетаний; загрузка текстов не делает предварительные LLM-метки истинными.

## Проверки

```bash
python3 -m unittest discover -s scripts/tests -p test_quality_news_batch.py -v
```

Все тесты полностью offline, имитируют ответы публичного fetcher и проверяют: teacher-label isolation, allowlist, явное подтверждение, защиту от подмены, отказ от перезаписи, экранирование HTML, отсутствие вымышленных дат и обработку ошибок.
