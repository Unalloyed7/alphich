# Alphich — финальная приёмка полного стенда

Рекомендация: провести приёмку на актуальном `main`, сохранив существующий PostgreSQL volume. **Не запускать** `docker compose down -v`. Облачная/публичная эксплуатация — отдельный этап: текущие демосессии не являются полноценной авторизацией для публичного стенда.

## Уже проверено на Mac (21 октября 2026)

- 5 сервисов Docker, импорт `DEMO_A`, обработка публикаций и доступ к сохранённому источнику, feed, ACL и бюджет — локальный бесплатный smoke.
- Qwen/GLM в режиме `gateway_receipt`, локальный E5 и банковский индекс — настроены; `bank_index_present=true`.
- После интеграции агентской сети подтверждены реальная карточка ключевой ставки, цитируемая банковская позиция, раскрытие evidence и **один успешный оплаченный уточняющий вопрос**. Повторно запускать модели для доказательства этого факта не требуется.
- CI в `main` (`.github/workflows/ci.yml`): backend/OpenAPI, React build, мокированные контрактные проверки и Docker smoke **без LLM**.

## Обновить стенд и прогнать бесплатно

```bash
git switch main
git pull --ff-only origin main
docker compose up -d --build
docker compose ps
python3 scripts/verify-stack.py --import-fixtures
python3 scripts/verify-personas.py
```

Последняя команда по умолчанию **не отправляет публикации и не вызывает модели**. Она создаёт четыре краткоживущие демосессии и проверяет 4 сочетания `DEMO_A/DEMO_B × cfo/ceo`, свой профиль, feed, отказы доступа к чужим профилям/лентам/событиям/источникам. Если в компании ещё нет событий, часть проверок помечается `SKIP`. Для гарантированного покрытия пустой компании можно отдельно запустить:

```bash
python3 scripts/verify-personas.py --seed-missing
```

`--seed-missing` только добавляет одну **синтетическую** публикацию в компанию без событий и ожидает ingestion worker; платных запросов нет. CI использует эту опцию на временной БД.

Если ранее сформированный **CFO**-инсайт для `DEMO_A` виден в feed, тест также читает карточку, фрагмент evidence и агентский журнал и проверяет, что `DEMO_A/CEO` и `DEMO_B/CFO/CEO` получают отказ (`404`), а не чужие данные. Для гарантированной строгой проверки сохранённого инсайта:

```bash
python3 scripts/verify-personas.py --require-insight
# При необходимости укажите ранее существующий ID из GET /insights, без запуска LLM:
python3 scripts/verify-personas.py --insight-id 'insight_ID' --require-insight
# Для уже сохранённого ответа (если известен ID):
python3 scripts/verify-personas.py --insight-id 'insight_ID' --answer-id 'answer_ID'
```

**Не подставлять вымышленные ID буквально**. Сам скрипт не читает API-ключи и не печатает токены демосессий. `--require-insight` специально падает, если сохранённую карточку не нашли. В CI платной карточки нет, поэтому эта опция не включается.

## Ручной браузерный протокол (4 сессии)

| Персона | Проверка в браузере | Ожидаемый результат |
| --- | --- | --- |
| `DEMO_A / CFO` | Профиль → лента → ранее проанализированная новость → evidence → run → сохранённый ответ | Карточка, финансовые основания, ограничение условий, ссылка на фрагмент; без повторной генерации |
| `DEMO_A / CEO` | «Завершить сессию» → вход как CEO → лента/события | Профиль той же компании, роль CEO; ранее готовый **CFO**-инсайт не раскрывается этой роли |
| `DEMO_B / CFO` | Завершить сессию → выбрать `DEMO_B` и CFO | Другая компания, свой профиль и лента; события и результаты `DEMO_A` недоступны |
| `DEMO_B / CEO` | Завершить сессию → `DEMO_B` и CEO | Профиль CEO, без данных другой компании и чужих AI-результатов |

После каждой смены пользователя проверить, что UI не показывает предыдущую карточку/вопрос из локального React state, что Network использует **новый** `X-Demo-Session`, а пользователь не видит чужих событий. Не публиковать токены или ключи на скриншотах.

Если готовые карточки существовали только для `DEMO_A/CFO`, отсутствие карточки для трёх других персон **ожидаемо**. Оно не доказывает неисправность AI и не требует трёх платных генераций.

## Протокол результатов для защиты

Запишите версию коммита (`git rev-parse --short HEAD`), дату и окружение, снимки экрана: новую публикацию/источник, персональную ленту, карточку с пометкой условий, один открытый банковский evidence с датой/страницей, успешный вопрос и ответ, профиль после смены роли, отказ в доступе другой компании, сводку бюджетного режима (без ключа). Тесты «PASS» не заменяют экспертную оценку финансовой корректности: старые 24 учебных сценария не подтверждают качество на новых реальных новостях.

Одна живая цепочка уже подтверждена скриншотами. Следующие оплачиваемые вызовы Qwen/GLM допускаются **только отдельно и с разрешения владельца общего бюджета**; обычная приёмка и CI по умолчанию бесплатны.
