# Разбор Alphich и переработка интерфейса

Дата: 22 октября 2026. Проверены рабочая копия, текущая ветка GitHub, PDF задания и материалы из двух предоставленных папок Google Drive. Доступа к содержимому других чатов проекта в этой сессии нет.

## Главный вывод

В репозитории уже есть существенная аналитическая логика: проверяемые факты, персональный отбор, поиск по материалам банка, отдельная верификация и бюджет. Старый первый экран показывал преимущественно состояние обработки публикаций. Пользователь видел устройство прототипа раньше, чем его пользу.

Для руководителя основной объект — влияние события на свой бизнес. Поэтому интерфейс перестроен вокруг последовательности «событие → влияние → следующий шаг». Более подробные факты, источники и трассировка доступны по запросу.

## Как устроен основной путь

1. Сервер создаёт демосессию для разрешённой компании и роли. Клиент хранит токен в `sessionStorage` и передаёт `X-Demo-Session`.
2. Публикация сохраняется вместе с первоисточником. Статус задания читается отдельно от события.
3. Извлечение получает дословные фрагменты и структурированные атрибуты. Проверка атрибутов не означает ручную проверку истинности новости.
4. Selector сопоставляет факты с признаками компании. Hybrid-поиск объединяет лексические и векторные ранги; при недоступности encoder предусмотрен лексический fallback.
5. Значимость ограничивается географией, масштабом, стадией события и применимостью. В текущем контракте в ленту проходят оценки 4–5. Оценка 5 требует подтверждённой применимости и конкретного действия.
6. Аналитический процесс получает бизнес-контекст, ищет разрешённую позицию банка и формирует условные интерпретации. Отдельный verifier проверяет их поддержку.
7. Сохранённая карточка содержит факты новости, факты компании, позицию банка, интерпретацию модели, риски, возможности, шаги и недостающие данные. Evidence и журнал доступны отдельными чтениями.
8. Пользователь задаёт уточняющий вопрос по конкретной карточке; это явная операция с собственным ключом идемпотентности.

## Что в архитектуре уже полезно

- Подтверждённый факт отделён от гипотезы. Наличие кредитного продукта не превращается в известную сумму долга или плавающую ставку.
- Scope компании, роли, времени и разрешённых документов задаётся сервером.
- Ранги поиска не выдаются за доказательство финансового влияния.
- Позиция банка имеет временной контекст; исторический материал не должен подменять актуальный прогноз.
- Сетевой сбор ограничен списком хостов, размером ответа и публичными адресами. Ключи моделей остаются на сервере.
- Платные действия отделены от чтения сохранённых данных и используют Idempotency-Key.
- Есть самостоятельные проверки данных, API, retrieval и аналитики. В README корректно отмечено, что независимая оценка качества ещё не проведена.

Это основания сохранять существующий backend-контракт при изменении подачи. Улучшение внешнего вида само по себе не доказывает качество модели или полноту новостного покрытия.

## Визуальная система

Тёплый светлый фон, белые карточки, графитовая типографика и красный акцент. Приглушённая зелёная поверхность выделяет бизнес-контекст. Слоган «Меньше шума. Больше ясности.» задаёт смысл обзора; вход использует «Новости, которые имеют значение».

Для заголовков и основного текста используются системные шрифты, для акцентной строки — Georgia. Интерфейс не зависит от загрузки внешних шрифтов. Орбиты и знак α — декоративная графика CSS/SVG; вымышленные графики доходности и неподтверждённые денежные показатели не добавлены.

Первый экран сокращён по высоте, чтобы пользователь быстрее достигал первой карточки. Обзор показывает до трёх событий; полная лента доступна отдельным действием. Ограничение текста анонса визуальное: полный текст доступен в событии и обосновании.

## Найденное несовпадение запущенного стенда

На локальных `8000` и `5173` уже работают Docker-сервисы. Для нового предпросмотра использован отдельный порт `5174`.

Живой API отвечает на health и принимает `DEMO_A`, но отклоняет `U_9250` по allowlist. Его feed возвращает записи без новых полей `relevance_grade`, а чтение `/companies/{id}/discovery` отвечает 404. Это свидетельство несовпадения запущенного API с контрактом текущего checkout.

UI не подставляет отсутствующие оценки. При недоступном подборе показывает понятное сообщение и отключает запуск. Для полноценного интеграционного демо требуется согласованная пересборка сервисов из одной версии репозитория; в этой работе уже запущенные контейнеры не заменялись. Платные генерации на живом шлюзе не запускались.

## Следующие продуктовые проверки

1. На актуальном интеграционном стенде пройти новую реальную публикацию → карточку → evidence → вопрос. Зафиксировать качество, время и расход отдельно от тестов UI.
2. Дать участнику команды без объяснений три задания: найти важное событие, понять влияние, открыть источник. Измерить время и ошибки, а не оценивать дизайн только по скриншоту.
3. Проверить две роли на одной новости и две компании на одном событии: различия должны объясняться доступными признаками.
4. Перед защитой проверить исторический банковский материал, отсутствие позиции банка, неполный текст и отказ модели.
5. Отдельно подтвердить интеграцию входа в настоящий интерфейс Альфа-Бизнеса: текущий результат остаётся самостоятельным прототипом Alphich.
