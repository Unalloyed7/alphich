# Alphich: независимая оценка релевантности (P0)

Локальный инструмент без внешних зависимостей, без Cloud.ru и без платных LLM-запросов. Использует **оригинальные** `knowledge/fixtures/real_news_selection_labels.v2.json` и `.v3.json`, не изменяя их. Всего ожидается 62 новости × 3 компании = **186 пар** (150 + 36). Первоначальные метки агентской разметки **не** считаются экспертной истиной.

## Запуск на Mac из корня репозитория

```bash
python3 scripts/quality_review.py init \
  --fixtures-dir knowledge/fixtures \
  --db data/private/quality-review.sqlite3 \
  --reviewers expert_a expert_b \
  --arbiter reviewer_lead

python3 scripts/quality_review.py serve --db data/private/quality-review.sqlite3
```

Откройте **http://127.0.0.1:8765/**. При `init` один раз печатаются три уникальных токена — их следует передать пользователям по защищённому каналу, но **не хранить в Git, issue или чат-боте**. Каждый эксперт вводит свой токен. Разметку можно проводить по очереди на **одном локальном компьютере**. Если эксперты работают на разных компьютерах, настройте локальную передачу БД/безопасный доступ отдельно; нельзя просто открыть порт публично. Нет облачных учётных записей и централизованной аутентификации. Токен не записывается в `localStorage` и не добавляется в URL; после закрытия вкладки его нужно ввести снова.

Программа принудительно привязана к `127.0.0.1` и не выдаёт доступ к файлам, исходным AI-меткам или чужим отзывам из API эксперта. Арбитр видит обе оценки **после** их сохранения. Согласованные оценки (одинаковая цифра и три признака) становятся итоговыми без арбитра; при расхождении арбитр сохраняет собственное окончательное решение. Исправление своего решения до арбитража добавляет новую ревизию, не перезаписывая историю. Оригинальная оценка AI доступна **только оператору через опциональный offline экспорт**, а не через интерфейс.

Сохранённая БД — `data/private/quality-review.sqlite3` (права `0600`), путь игнорируется Git; в ней хранятся токен-хеши, оригинальные оценки AI (для **последующего** сравнения), история решений. Сохраните её резервную копию **вне репозитория**. Поскольку приложению не нужен интернет, его запуск не расходует бюджет модели.

## Что известно из исходных JSON

В v2/v3 есть заголовок, адрес оригинала, ID события, ID компании, исходные оценки и обоснования AI. **Полного текста новости, даты публикации и независимо подтверждённого профиля компаний наборы не содержат**. Нельзя выдавать дату, восстановленную из URL, за подтверждённую. В форме дата обозначена как отсутствующая; источник открывается отдельной ссылкой с `rel=noopener noreferrer`.

Для воспроизводимой полной проверки желательно заранее загрузить **независимые** снимки статей и признаки компаний в приватных JSON, полученных из разрешённых источников (не из полей `grades/rationale/assessment`):

Пример `data/private/review_articles.json`:
```json
{
  "event_v3_example": {
    "text": "Проверенный полный текст статьи из первоисточника",
    "published_at": "2026-10-08"
  }
}
```

Пример `data/private/review_company_context.json`:
```json
{
  "U_201985": {
    "verified_at": "2026-10-22",
    "features": [
      {"name": "okved_code", "value": "41.20.1", "source_ref": "Источник и версия проверенного профиля"},
      {"name": "registration_region", "value": "Москва", "source_ref": "Источник регистрации (НЕ доказательство операций)"}
    ]
  }
}
```

Значения в примере — **иллюстрация формата, не новые проверенные факты для оценки**. Перед использованием сверяйте их с исходными разрешёнными данными. Не включайте в эти JSON банковские секреты, выписки или неразрешённые данные.

До начала разметки включите оба файла прямо в `init` через `--articles data/private/review_articles.json --contexts data/private/review_company_context.json`. Можно выполнить отдельную команду (только пока никто не оставил оценку):

```bash
python3 scripts/quality_review.py enrich \
  --db data/private/quality-review.sqlite3 \
  --articles data/private/review_articles.json \
  --contexts data/private/review_company_context.json
```

Если данные неполны, интерфейс честно помечает пробелы. Не присваивайте 4–5 на основании несуществующей в материалах экспозиции компании.

## Рабочий процесс

1. Эксперт A входит по своему токену, оценивает пары 0–5 и обязательные ограничения по географии, масштабу, применимости; поясняет выбор. Он **не видит AI-метку и оценку эксперта B**.
2. Эксперт B независимо выполняет ту же работу. Он не видит AI-метку и оценку эксперта A.
3. Арбитр входит по собственному токену, видит завершённые пары и обе оценки. Разрешает разногласия; автоматическое согласие определяется совпадением балла и трёх структурных измерений. Если обоснования даже согласованных оценок различаются, арбитр должен вручную проверить это до публикации набора.
4. Оператор выгружает результат и историю ревизий командой ниже. **Неполный набор `complete=false` нельзя выдавать за gold benchmark**.

```bash
python3 scripts/quality_review.py export \
  --db data/private/quality-review.sqlite3 \
  --output data/private/quality-review-export-20261022.json
```

Для аналитического сравнения с AI после завершения независимой работы можно создать **новый файл** с `--include-predictions`. Выгрузка содержит `schema_version`, версии и SHA-256 обоих корпусов, все состояния пар, `gold` только для согласованных или прошедших арбитраж, а также полный append-only журнал всех ревизий.

Выгрузка не запускает модели. Не коммитьте её в публичный репозиторий без отдельной проверки прав на данные/содержимое.

## Ограничения P0

- Работа локальная и рассчитана на доверенный компьютер. Это **не многопользовательская интернет-система**. Пересылка токенов и БД — ответственность оператора.
- Протокол `reviewer`, `arbiter` разделяет роли и не передаёт peer-review до нужного этапа; SQL-файл открыт своему владельцу ОС, поэтому не защищает от оператора машины. По-настоящему независимая процедура требует организационного контроля.
- При несовпадении *обоснований*, но совпадении балла и категорий программа отмечает `agreed`. Рекомендуется проверять такие пары при арбитраже вручную.
- `date` и `company_context` надо дополнить из независимо проверенных источников. При отсутствии этих данных метрика качества не должна притворяться полной.
- Отчёты precision/recall и матрица ошибок — отдельный **PR 2**. Исходные 9 позитивных AI-разметок не являются достаточным набором для уверенной оценки полноты.
- Не трогаем `financial_grounding.py`, `agent.py`, `service.py`, `schemas.py`, `personalization/business.py`, а также продовую БД.
