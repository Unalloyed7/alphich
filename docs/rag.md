# Поиск банковских доказательств

В `knowledge/` работает локальный поиск по экспертным PDF: E5 кодирует запрос, точный векторный поиск находит фрагменты, реестр подбирает проверенные тезисы с нужным горизонтом, а модуль собирает контекст с цитатами для генеративной модели. Доступны режимы `dense`, `lexical` и `hybrid` с RRF. По результатам небольшого открытого набора для этого банковского корпуса по умолчанию выбран `dense`; режим новостного отбора этим экспериментом не оценивался.

Готовый локальный индекс — `data/processed/bank-index-v1`: 149 поисковых фрагментов и 9 проверенных выдержек, всего 158 векторов размерности 768. Образец контекста для запроса прогноза ставки находится в `data/processed/rag-demo-current.json`. Поиск подключён к [LLM worker и API карточек](llm.md); до получения доступа к шлюзу генеративный этап проверяется тестовыми ответами.

## Запуск

Из корня репозитория после [подготовки PDF](knowledge-base.md):

```sh
knowledge/.venv/bin/python -m pip install -r knowledge/requirements-rag.lock

PYTHONPATH=knowledge/src knowledge/.venv/bin/python -m alphich_kb fetch-encoder

PYTHONPATH=knowledge/src knowledge/.venv/bin/python -m alphich_kb index \
  --corpus-dir data/processed/bank-kb-v1 \
  --output-dir data/processed/bank-index-v1

PYTHONPATH=knowledge/src knowledge/.venv/bin/python -m alphich_kb retrieve \
  --index-dir data/processed/bank-index-v1 \
  --query 'Какую ставку банк ожидает к концу 2026 года?' \
  --as-of 2026-10-20 --metric policy_rate --horizon 2026-12-31 \
  --context-only
```

Выходной каталог индекса должен быть новым. Если он уже существует, готовый индекс можно сразу использовать для `retrieve`. `fetch-encoder` скачивает закреплённые файлы с проверкой SHA-256 и проверяет уже имеющиеся. Работа после загрузки весов полностью локальная, ключ генеративной модели для поиска не нужен.

Модель — официальный ONNX INT8 экспорт `intfloat/multilingual-e5-base`, revision и hash в `knowledge/embedding-model.json`. Файл называется `model_qint8_avx512_vnni.onnx`; работоспособность проверена с ONNX Runtime CPU на macOS arm64. На целевом Linux стенде нужно проверить совместимость и производительность. Используются два CPU потока, маскированное усреднение и L2 нормализация. Запрос получает `query: ` один раз; подготовленные фрагменты уже содержат `passage: `. Вход длиннее 512 токенов отклоняется. Для индексации по умолчанию используется batch size 4.

Пакеты retrieval являются отдельной optional dependency group: `pip install -e 'knowledge[retrieval]'` подходит для установки в окружение приложения. Для зафиксированного графа зависимостей используйте `knowledge/requirements-rag.lock`. Базовый OCR пакет сохраняет собственный более короткий lock.

## Подключение к бэкенду

Создайте один encoder и retriever на выделенный worker, затем передавайте scope из проверенных сервером прав и даты задачи:

```python
from alphich_kb.embeddings import E5Encoder
from alphich_kb.retriever import BankRetriever, RetrievalScope
from alphich_kb.context import context_for_model

encoder = E5Encoder(model_dir="data/models/e5-base")
retriever = BankRetriever("data/processed/bank-index-v1", encoder)

# Пример scope для этого запроса; в приложении набор ID приходит из авторизации.
scope = RetrievalScope(
    as_of="2026-10-20",
    allowed_document_ids=frozenset({"policy_rate_20260911", "macro_1h2026"}),
)
result = retriever.retrieve(
    "Какую ставку банк ожидает к концу 2026 года?",
    scope,
    metric="policy_rate",
    horizon="2026-12-31",
)
generation_context = context_for_model(result)
```

`generation_context` передаётся адаптеру разрешённой LLM вместе с фактами события, проверенными признаками компании и заданием анализа. Результат поиска не содержит личного вывода для клиента. Вызов платной генеративной модели и валидация её ответа остаются в агентном runtime.

Для локальной CLI по умолчанию разрешены все документы этого банковского индекса. `--allow-document ID` сужает набор; флаг можно повторять. Python API требует явный `RetrievalScope`. Он фиксирует календарный день анализа и разрешённые документы; аргументы инструмента LLM не должны менять этот объект. Внутри дня точное время публикации PDF неизвестно: timestamp задачи нельзя автоматически превращать в разрешение использовать все материалы этого дня. Для строгой внутридневной истории нужны дополнительные сведения о времени доступности.

При неизвестной дате публикации документ исключается. Фильтры применяются до top-K в обеих поисковых ветках, при выборе тезисов, выдаче evidence и расширении parent. Фильтр тем ограничивает кандидатов; обновления запрошенного показателя ищутся по всему разрешённому датированному корпусу, чтобы узкий тематический фильтр не скрыл пересмотр прогноза. Доступ и дата при этом сохраняются.

## Что возвращается

| Поле | Содержимое |
| --- | --- |
| `hits` | Поисковые кандидаты, дата, страница, совпавшие фрагменты и ранги каждой ветки |
| `bank_claims` | Проверенные тезисы для явно запрошенного показателя и горизонта |
| `evidence` | Точные исходные выдержки с неизменяемыми ID и source refs |
| `parent_contexts` | Окна вокруг совпадений с собственными span ID и смещениями в странице |
| `bank_view_status` | `found`, `historical_only`, `conflicting` или `not_found` в разрешённом загруженном корпусе |
| `mode` | Фактически использованный режим, включая `lexical_fallback` |
| `trace` | Версии, scope, критерии, отказы тезисов, выбранные ID и время поиска |

Для прогноза задавайте `metric` и `horizon`. Без горизонта прогнозы не превращаются в выбранную позицию банка. Для качественной интерпретации можно задать только показатель, например `metric=fuel_inflation_risk`. Результат без подходящего проверенного тезиса имеет `candidates_only` либо `not_found`; поисковое совпадение само по себе не подтверждает мнение банка.

Реестр подтягивает допустимый пересмотр, даже если его страница не вошла в поисковый top-K. На текущем корпусе запрос ставки на конец 2026 года возвращает 13,5% при дате анализа 1 августа и 14% при дате 20 октября. Прогноз 12% на конец 2027 года имеет другой горизонт. Прогноз недельной инфляции на 1–7 сентября при анализе 20 октября помечается `historical_only`. Это атрибутированные оценки из предоставленных документов; они не устанавливают текущую позицию всего банка.

Обычный OCR остаётся непроверенным. Проверка одного фрагмента не распространяется на соседнее окно parent: у расширенного окна `ocr_checked=false` и собственный evidence ID. `get_evidence(id, scope)` повторно проверяет доступ и дату. Backend должен сохранять выданные окна и trace вместе с карточкой; память процесса держит ограниченный кэш окон, а не постоянное хранилище пользовательских карточек.

`context_for_model` исключает отладочные `hits` и trace, помечает источники как недоверенные данные и включает только отобранные evidence и контекст. Общий бюджет исходного текста по умолчанию — 16 000 Unicode символов; метаданные и токены генеративной LLM в него не входят. Проверенные тезисы получают приоритет. Если их цитата не поместилась, сам тезис тоже не передаётся. Runtime дополнительно ограничивает весь prompt токенизатором выбранной генеративной модели и проверяет ссылки в ответе.

## Хранение и отказоустойчивость

Индекс содержит `vectors.npy` с float32 L2 векторами, `items.jsonl`, `embedding_records.jsonl`, страницы, метаданные документов и реестр тезисов. Он самодостаточен для поиска; изображения OCR и оригинальные PDF передаются отдельно для просмотра. Векторная матрица читается через mmap с `allow_pickle=False`. Для 158 записей используется точное скалярное произведение по предварительно отфильтрованным строкам.

Каждая запись embedding содержит owner ID/version, hash закодированного текста, embedding space и строку матрицы. Пространство закрепляет модель, revision, файлы, pooling, нормализацию, префиксы и runtime. Несовместимый query encoder или изменённый артефакт отклоняется. При росте корпуса эти записи и матрица пригодны для импорта в `vector(768)` PostgreSQL; текущий локальный модуль не требует отдельного сервера БД.

При операционном отказе encoder выдача явно переключается в `lexical_fallback`; режим включён в ID поиска. Ошибки целостности, другая модель и слишком длинный запрос не подменяются успешным семантическим поиском. Для воспроизведения сравнения `allow_fallback=False` запрещает замену dense результата текстовым. Кодировщик держит небольшой LRU кэш запросов; он не меняет ID источников.

Гибридная ветка сначала сворачивает совпадения каждой модальности до одного вклада страницы, затем объединяет ранги через RRF с `k=60`. Значения BM25 и cosine не складываются. Cosine не является вероятностью релевантности или ущерба компании.

## Измеренное качество

```sh
PYTHONPATH=knowledge/src knowledge/.venv/bin/python -m alphich_kb compare-retrieval \
  --index-dir data/processed/bank-index-v1

PYTHONPATH=knowledge/src knowledge/.venv/bin/python -m unittest discover -s knowledge/tests -v
```

Разметка — `knowledge/retrieval_cases.json`, полный отчёт — `knowledge/retrieval_report.json`. Все режимы сравниваются на одном индексе, включая проверенные выдержки, с одинаковыми фильтрами и лимитом. Набор открытый: 17 вопросов с размеченными страницами и 10 контрольных случаев. Не все альтернативные подходящие страницы размечены; это проверка разработки, не независимый benchmark и не оценка персонализации новостей.

| Режим | Найдена размеченная страница в top-5 | Средний recall@5 | MRR@5 | Контрольные случаи |
| --- | --- | --- | --- | --- |
| Lexical | 12/17 | 0,647 | 0,520 | 10/10 |
| E5 dense | 16/17 | 0,912 | 0,631 | 10/10 |
| Hybrid RRF | 15/17 | 0,853 | 0,605 | 10/10 |

Начальная конфигурация hybrid уступила dense на этом наборе. Временный default `dense` выбран для текущего банковского корпуса. При добавлении материалов и независимой разметки режим и настройки нужно оценить заново. Вопрос о замедлении роста расходов покупателей пропустили все три режима: этот провал сохранён в отчёте.

На macOS arm64 с двумя потоками кодирование индекса заняло 26,6 секунды; в отдельном процессе этого запуска наблюдался пик RSS 720 715 776 байт, около 687 МиБ. В процессе сравнения пик RSS составил около 801 МиБ. Для прогретого encoder без query cache измерены медианы 7,5 мс lexical, 8,1 мс dense и 14,6 мс hybrid; загрузка модели и индекса исключена. Это один локальный прогон, а не характеристики целевого сервера. Генеративная LLM в измерениях не участвовала.

Официальные основы: [E5 и masked mean pooling](https://huggingface.co/intfloat/multilingual-e5-base), [ONNX Runtime CPU inference](https://onnxruntime.ai/docs/api/python/api_summary.html), [pgvector и hybrid search](https://github.com/pgvector/pgvector#hybrid-search).
