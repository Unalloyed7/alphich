# Подготовка экспертной базы для RAG

Инструмент в `knowledge/` распознаёт экспертные PDF и готовит JSONL для импорта в бэкенд. Это отдельный Python пакет; он не меняет API, базу приложения или агентный runtime. Генеративных вызовов и расходов на LLM при подготовке нет.

В корпусе организаторов девять документов и 64 страницы. `knowledge/corpus.json` фиксирует SHA-256 каждого PDF, название, исходный URL, количество страниц, дату публикации и темы. Даты прочитаны со страниц. У обзора золота дата публикации неизвестна: август 2026 на обложке обозначает период обзора.

Готовый локальный снимок: `data/processed/bank-kb-v1`, изображения и TSV: `data/processed/bank-ocr-v1`. Получены 149 поисковых фрагментов, 9 проверенных выдержек и 12 утверждений. Исключены 11 служебных страниц и обложек. На десяти открытых контрольных сценариях все проверки пройдены; для пяти положительных вопросов recall@5 = 1,0 и MRR = 0,75. Это результат небольшого набора разработки; полный отчёт находится в `knowledge/evaluation.json`.

## Запуск

Нужны Python 3.12+, `curl`, Poppler (`pdfinfo`, `pdftoppm`) и Tesseract 5. На macOS:

```sh
HOMEBREW_NO_AUTO_UPDATE=1 HOMEBREW_NO_INSTALL_CLEANUP=1 brew install tesseract poppler
```

Для Debian/Ubuntu зависимости устанавливаются пакетами `poppler-utils` и `tesseract-ocr`. Русские и английские языковые данные скачиваются отдельно по `knowledge/assets.json`; устанавливать все языки не требуется.

Из корня репозитория:

```sh
python3 -m venv knowledge/.venv
knowledge/.venv/bin/python -m pip install -r knowledge/requirements.lock

PYTHONPATH=knowledge/src knowledge/.venv/bin/python -m alphich_kb fetch

PYTHONPATH=knowledge/src knowledge/.venv/bin/python -m alphich_kb extract \
  --output-dir data/processed/bank-ocr-v1

PYTHONPATH=knowledge/src knowledge/.venv/bin/python -m alphich_kb build \
  --ocr-dir data/processed/bank-ocr-v1 \
  --output-dir data/processed/bank-kb-v1
```

`fetch` проверяет существующие файлы и скачивает отсутствующие с проверкой SHA-256. Изменённый PDF не заменяет закреплённый оригинал. Для обновления корпуса требуется новый манифест и новая проверка.

`extract` рендерит страницы при 240 DPI и запускает Tesseract `rus+eng`, OEM 1, PSM 3, два процесса одновременно. Выход содержит PNG, TSV с координатами слов, `documents.jsonl` и `pages.jsonl`. Порядок чтения определяется OCR; многоколоночные таблицы требуют проверки по изображению. Уверенность Tesseract — диагностический показатель распознавания, а не вероятность истинности утверждения.

`build` создаёт новый неизменяемый снимок. Повторный запуск требует нового выходного каталога. Перенарезка не требует повторного OCR. `knowledge/reviews.json` привязан к точным версиям распознанных страниц: после изменения движка, DPI или текста старые проверки нельзя автоматически перенести.

Первый снимок распознан Tesseract 5.5.2 и Poppler 26.07.0 на macOS arm64; версии языковых данных и токенизатора закреплены контрольными суммами. Другие сборки инструментов могут изменить OCR и версии страниц. Для такого запуска сначала используйте файл проверок с пустыми `claims` и `page_sections` через `--reviews`, затем выполните новую сверку. Для интеграции без повторного OCR передавайте бэкендеру готовые каталоги снимка и изображений. Контейнерная сборка OCR в этой итерации не проверялась.

## Формат передачи бэкендеру

| Файл готовой базы | Назначение |
| --- | --- |
| `documents.jsonl` | Метаданные источников, даты, URL, hash оригинального PDF и версия извлечения |
| `pages.jsonl` | Полный текст страницы, ID parent, координаты строк, версия OCR и путь к изображению |
| `chunks.jsonl` | Поисковые фрагменты, точные смещения в странице, готовый вход E5, число токенов |
| `evidence.jsonl` | Отдельные выдержки, проверенные по изображению; пригодны как подтверждение размеченных тезисов |
| `claims.jsonl` | Размеченные утверждения: автор, показатель, значение, горизонт, роль и связи пересмотра |
| `quality.json` | Объём корпуса, исключённые страницы, неизвестные даты и качество OCR |
| `manifest.json` | Версия базы, конфигурация токенизатора/нарезки и контрольные суммы выходных файлов |

Импортировать поисковые фрагменты и проверенные выдержки нужно по их полному `id`; ссылки из `claims.document_chunk_id` ведут в `evidence.jsonl`. `parent_id` ведёт в `pages.jsonl`. Изображения лежат в каталоге OCR: путь из `source_refs.image` отсчитывается от него, а не от каталога готовой базы. Для просмотра оригинала используются URL документа и отдельный номер страницы; фрагмент `#page` в Google Drive не гарантирует переход на страницу.

`source_span.start/end` — полуинтервал индексов Unicode code points в точной строке `pages.text`, как Python `text[start:end]`. В JavaScript это не всегда индексы UTF-16: при наличии символов вне BMP требуется преобразование. Координаты `bbox` имеют формат `[left, top, width, height]` в пикселях сохранённого PNG.

Имена `document_id` стабильны в корпусе, версии и evidence ID неизменяемы. Изменение исходника, метаданных, OCR или конфигурации нарезки создаёт новые версии. При импорте снимка проверяйте контрольные суммы из манифеста.

## Нарезка и проверка чисел

`embedding_text` уже начинается с `passage: ` и содержит заголовок, дату и страницу. Добавлять префикс повторно не нужно. Размер проверяется настоящим токенизатором `intfloat/multilingual-e5-base`, закреплённым по revision и SHA-256, с учётом специальных токенов. Усечение и padding отключены. По умолчанию бюджет всего входа — 384 токена, предельный допустимый — 512. Это подготовка входов; эмбеддинги и индекс здесь не вычисляются.

Фрагменты сохраняют границы абзацев, предложений и строк, где это позволяет лимит. Последнее предложение или строка может повторяться в следующем фрагменте в пределах четверти бюджета. Длинные блоки разрезаются без потери символов; parent сохраняет полный контекст страницы. Темы фрагмента наследуются от документа и помечены `topics_scope=document_inherited`: это не автоматическая классификация конкретного тезиса. Горизонт фрагмента остаётся `null`; разные прогнозы одной страницы разделены в реестре утверждений.

Все обычные OCR-фрагменты имеют `ocr_checked=false`. Например, в макрообзоре `0,1%` местами распознано как `01%`: такой текст помогает найти страницу, но не подтверждает точное число. Ручная проверка небольшого span не переводит всю страницу или соседние фрагменты в проверенное состояние.

`reviews.json` содержит точную OCR-цитату, hash оригинала и версию страницы, нормализованное утверждение, автора и заметку о визуальной сверке. Переписывать число в цитате нельзя: цитата должна точно находиться в тексте. Если OCR исказил существенное число, этот span не включается в реестр до исправления текста с выпуском новой версии и новой проверки. Поля утверждения — доверенная ручная разметка; код проверяет привязку и согласованность метаданных, а не самостоятельно доказывает смысл ручной записи.

## Даты и пересмотр прогнозов

Прогноз на конец 2026 года и прогноз на конец 2027 года имеют разные горизонты. Старое мнение, процитированное в новом PDF, помечается `previous_view`. Решение ЦБ внутри банковского обзора атрибутируется ЦБ, а не превращается в мнение банка.

`revision_of` допустим для совпадающих автора, показателя, географии, сценария, единицы и горизонта, с переходом к более раннему датированному документу. Фильтр `as_of` применяется до обхода пересмотров. Отбор возвращает все оставшиеся подходящие позиции: независимые противоречащие прогнозы нельзя автоматически объявить одним актуальным мнением.

```sh
PYTHONPATH=knowledge/src knowledge/.venv/bin/python -m alphich_kb claims \
  --corpus-dir data/processed/bank-kb-v1 \
  --as-of 2026-10-20 --metric policy_rate --horizon 2026-12-31
```

Точность временного фильтра — календарный день. Для исторического анализа внутри дня серверу нужна отдельно подтверждённая дата и время доступности; дата PDF не доказывает доступность к началу этого дня. Материалы с неизвестной датой исключаются из строгого датированного поиска. Старый материал 2021 года может служить историческим контекстом, но дата должна оставаться видимой; наличие в выдаче не подтверждает его актуальность для сегодняшнего рынка.

## Проверки поиска

```sh
PYTHONPATH=knowledge/src knowledge/.venv/bin/python -m alphich_kb search \
  --corpus-dir data/processed/bank-kb-v1 \
  --query 'ключевая ставка прогноз' --as-of 2026-10-20

PYTHONPATH=knowledge/src knowledge/.venv/bin/python -m alphich_kb evaluate \
  --corpus-dir data/processed/bank-kb-v1

PYTHONPATH=knowledge/src knowledge/.venv/bin/python -m unittest discover -s knowledge/tests -v
```

Поиск — локальный baseline SQLite FTS5 с prefix match и BM25, без русской морфологии и dense retrieval. До ранжирования применяются дата и необязательный фильтр тем; перекрывающиеся результаты одной страницы схлопываются. Контакты, дисклеймеры и обложки исключаются по явной разметке страниц, а не по решению LLM. Бэкендер может импортировать те же фрагменты в PostgreSQL FTS/pgvector и сравнить baseline с E5/hybrid.

`eval_cases.json` — небольшой открытый набор вопросов к корпусу и сценариев пересмотра прогноза. Он проверяет найденные страницы, роль и горизонт; это набор разработки, не независимая оценка качества новых новостей или всей персонализации. В отчёте есть recall@K, MRR и результаты каждого случая.

Исходные PDF, языковые модели, полный OCR и готовые базы находятся в игнорируемых каталогах `data/raw`, `data/models`, `data/processed`. В Git передаются код, манифесты и ограниченная разметка проверок. Новые PDF сначала проходят извлечение, затем проверку существенных тезисов; наличие OCR само по себе не делает документ проверенной банковской позицией.

Источники параметров: [Tesseract CLI и TSV](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html), [карточка E5](https://huggingface.co/intfloat/multilingual-e5-base), [закреплённые языковые данные Tesseract](https://github.com/tesseract-ocr/tessdata_fast/tree/4.1.0).
