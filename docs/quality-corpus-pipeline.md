# Alphich — конвейер подготовки RSS-статей для независимой экспертизы (v1)

**Назначение:** заменить ручные выгрузки и копирование статей воспроизводимым циклом `RSS на Cloud.ru → приватный снимок → сопоставление → просмотр → явное подтверждение → Quality Lab → ML-export`. Скрипт `scripts/quality_corpus_pipeline.py` работает без внешних Python-зависимостей и не вызывает LLM, не меняет production Postgres и не затрагивает `knowledge/src/alphich_kb/relevance_ml/` либо `discovery.py`. Подтверждения людей и модель принадлежат отдельным рабочим потокам.

## Что уже есть и чего нет

Проверенное исходное состояние: на Cloud.ru обнаружено 108 записей в `rss_articles`, из них 3 в `rss-smoke.*`, 105 остальных; 37 точных URL совпали с 62 статьями v2/v3. На Mac уже перенесён `data/private/rss-quality-matches.json` с данными **только этих совпадений**. Эти цифры — предыдущий замер, **не гарантированный результат нового запуска**.

Текущий Quality Lab принимает **только** существующие фиксированные v2/v3 и 3 компании. Поэтому новая программа:

- может автоматически подготовить тексты для существующих пар, но **не создаёт новые экспертные оценки**;
- складывает остальные статьи (когда `sync` запрашивает весь RSS) в **отдельный** `unmatched_rss_articles.jsonl` — без присвоения фальшивых меток или автоматического включения в старый benchmark;
- не расширяет Quality Lab новыми компаниями; для этого необходим следующий PR с версионированным реестром пар и миграцией UI/SQLite.

## Быстрое применение к файлу, который уже находится на Mac

После merge данного PR и `git pull --ff-only origin main`, из корня репозитория:

```bash
python3 scripts/quality_corpus_pipeline.py prepare \
  --rss-export data/private/rss-quality-matches.json \
  --run imported-37-v1
```

Вывод покажет `counts` с количеством `new`, `already_present`, `conflict`, `missing`, `ambiguous`; число `new_pair_texts` учитывает *все компании* одной новости. **Никаких изменений SQLite при `prepare`**.

Открыть локальное представление *новых* черновиков:

```bash
open data/private/quality-pipeline/imported-37-v1/preview.html
```

Результаты лежат в закрытом каталоге с правами `0700`, каждый файл `0600`:

| Файл | Что содержит |
|---|---|
| `manifest.json` | время, версии фикстур, SHA-256 экспорта, состояние по каждой новости |
| `candidate_articles.json` | полный текст новых совпавших статей, даты или `null` |
| `preview.html` | экранированный просмотр перед подтверждением человеком |
| `unmatched_rss_articles.jsonl` | другие статьи из RSS (без оценок); в старом экспорте из 37 статей может быть пустым |

Статус `already_present` означает, что такой текст уже сохранён. `conflict` означает различие с сохранённым текстом: **автоматическая замена запрещена**. `ambiguous` — несколько RSS-версий одного URL. `missing` — точного URL нет. Не пытайтесь разрешать конфликты по одному заголовку.

### Подтверждение и импорт

В `preview.html` сверьте текст, первоисточник, полноту и опубликованную дату (если она есть). После ручной проверки перечислите только одобренные `event_id` из `manifest.json`:

```bash
python3 scripts/quality_corpus_pipeline.py approve \
  --run imported-37-v1 \
  --ids EVENT_ID_1 EVENT_ID_2
```

Команда атомарно запишет только **отсутствующие** статьи в локальный `data/private/quality-review.sqlite3` и создаст audit metadata со списком event_id и хешем манифеста. При обнаружении существующего текста (даже отличающегося), изменённого снимка, версии фикстуры, или **хотя бы одной начатой человеческой оценки** импорт остановится. При повторе того же импорта не дублируются изменения. Существующие вручную подготовленные две статьи v3, если они отличаются, окажутся в `conflict`, а не будут затёрты.

`approve` означает, что оператор сверил оригиналы; программа не умеет автоматически установить, корректно ли извлечённый текст передаёт смысл новости. В случае неясности оставьте запись неподтверждённой. Не изменяйте JSON вручную после `prepare` — защитные SHA-256 не дадут импортировать подменённый текст.

## Следующие партии — одна команда, без INCY

Сразу на Mac, **после merge** и при наличии авторизованного SSH-ключа:

```bash
python3 scripts/quality_corpus_pipeline.py sync --run rss-2026-10-22-v1
```

`sync` выполняет *один* read-only SQL SELECT из `rss_articles` на Cloud.ru через существующее SSH-соединение и `sudo -n docker compose exec -T postgres psql`. Фиксированные SSH-параметры по умолчанию соответствуют серверу Alphich. Не передаёт пароли БД, не запускает сборщик и не делает интернет-запросов **с Mac**. На сервере нужна авторизация `sudo -n` **без интерактивного пароля**; если её нет, команда завершится ошибкой без импорта. Для совместимости с иной SSH-конфигурацией есть аргументы `--ssh-host`, `--ssh-user`, `--ssh-key`; не изменяйте права Docker/сервера только ради импорта без согласования администратора.

Выходной каталог:

```
data/private/quality-pipeline/rss-2026-10-22-v1/
├── rss_snapshot.jsonl                 # исходный неизменяемый серверный снимок
└── review/
    ├── candidate_articles.json
    ├── manifest.json
    ├── preview.html
    └── unmatched_rss_articles.jsonl
```

При успешном `sync` можно открыть `.../review/preview.html`, сверить статьи и вызвать `approve --run rss-2026-10-22-v1 --ids ...` — программа автоматически найдёт вложенный каталог `review`.

Если `sudo -n` недоступен, используйте уже перенесённый архив командой `prepare`; **не снимайте** ограничения доступа к Postgres и не публикуйте его порт. Новое имя `--run` необходимо для каждого снимка: повторный запуск не перезаписывает историю.

## Версии, утечки и границы автоматизации

- Для источников разрешены только явно перечисленные публичные HTTPS-домены. Новые домены требуют отдельного review кода/allowlist. Старые private/local/fake-IP адреса запрещены.
- Дата публикации может быть `null`; никакие даты не угадываются из URL. `content_hash` в RSS — отпечаток структуры публикации, **не обязательно SHA-256 одного `body`**. Для проверки переноса скрипт сам считает SHA-256 тела.
- В `model_inputs.jsonl` из `scripts/relevance_dataset.py` **не попадут** метки первоначального LLM. Их можно запросить отдельным teacher-export, но это не human gold. Тренировать на human gold можно только после двух независимых оценок/арбитража.
- Публикации из `rss-smoke.alphich-example.org` исключены из SQL-экспорта. Данные компаний или аккаунтов SQL не запрашивает.
- Новые перепечатки/парафразы необходимо группировать для split train/test; простой URL не обеспечивает семантической дедупликации.
- **Не отправляйте** `data/private/`, исходные тексты и профили в публичный GitHub или issue. Резервную копию SQLite храните отдельно и с ограниченным доступом.

## Проверки

```bash
python3 -m unittest discover -s scripts/tests -p 'test_quality_corpus_pipeline.py' -v
```

Тесты offline: без SSH и LLM. Проверяют неизменность базы при подготовке, импорт только одобренных текстов, сохранение прежних статей, отказ от подмен, валидацию URLs, версий и дат, HTML-экранирование, хранение unmatched-корпуса, блокировку после человеческих оценок, атомарность и безопасное поведение SSH.

После завершения настоящей человеческой проверки:

```bash
python3 scripts/relevance_dataset.py \
  --db data/private/quality-review.sqlite3 \
  --fixtures-dir knowledge/fixtures \
  --output-dir data/private/relevance-export-after-human-v1
```

Все операции выше относятся к локальному подготовительному конвейеру. **Не запускайте** `AI_AUTOMATION_ENABLED`, не подключайте платный классификатор и не обещайте precision/recall до независимой оценки на отложенных данных.
