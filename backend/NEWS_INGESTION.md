# Прием публикаций, очередь и worker (P0)

Реализован независимый от LLM вертикальный срез **публикация → DB → job → worker → raw event**. Результат работы worker — сохраненная новая публикация и **сырой, ещё не проанализированный event**. Ни одно поле не выдается за извлеченный или проверенный AI-факт.

## API

Все HTTP-маршруты начинаются с `/api/v1`. Для всех, кроме `health` и `demo-session`, требуется `X-Demo-Session`. `Idempotency-Key` обязателен для `POST /publications`, 8–128 символов (ASCII letters/digits/`._:-`). Токен получают через `POST /demo-session` для компании из серверного `DEMO_COMPANY_IDS`.

| Метод | Маршрут | Семантика |
| --- | --- | --- |
| POST | `/publications` | Принимает JSON `{title,text,source_url?,published_at?}` и отвечает HTTP **202** с job |
| GET | `/jobs/{id}` | Только автору демосессии: `queued/running/succeeded/failed`, `result_id` |
| GET | `/events/{id}` | Только в компании демосессии: сырой event с источником, без неподтвержденных фактов |
| GET | `/sources/{id}` | Только в компании демосессии: оригинальный текст и метаданные источника |

Пример:

```sh
# Запуск в корне репозитория, предварительно импортировав профили через app.importer
# Результат demo-session необходимо передать в переменную TOKEN.
TOKEN="YOUR_DEMO_TOKEN"

curl -i -X POST 'http://127.0.0.1:8000/api/v1/publications' \
  -H 'Content-Type: application/json' \
  -H "X-Demo-Session: $TOKEN" \
  -H 'Idempotency-Key: demo-key-2026-09-11-001' \
  -d '{
    "title":"Банк России сохранил ключевую ставку",
    "text":"Банк России сообщил о сохранении ключевой ставки на очередном заседании. Сведения об условиях кредитных договоров конкретных компаний в публикации не приводятся.",
    "source_url":"https://example.com/source",
    "published_at":"2026-09-11T12:30:00+03:00"
  }'

# Полученный id из ответа — JOB_ID:
curl -H "X-Demo-Session: $TOKEN" "http://127.0.0.1:8000/api/v1/jobs/$JOB_ID"
# После succeeded result_id — EVENT_ID:
curl -H "X-Demo-Session: $TOKEN" "http://127.0.0.1:8000/api/v1/events/$EVENT_ID"
```

В Docker worker работает отдельным сервисом. При локальном запуске API и worker должны иметь **одинаковый `DATABASE_URL`**:

```sh
cd backend
python -m app.worker --once            # попытаться выполнить одну задачу
python -m app.worker --poll-interval 1  # постоянно читать очередь
```

## Источники и ограничения

- `published_at` необязателен, но если задан, требует явный часовой пояс и нормализуется в UTC. `event_at` остается `null`: дата публикации сама по себе не подтверждает дату события.
- `received_at` — время принятия сервером. `fetched_at=null`: сервис не скачивает URL, даже если он указан. Ссылка отображается как **непроверенная** (`url_verified=false`).
- `completeness=user_supplied_text`: сервис не утверждает, что вставленный текст — полная публикация.
- `topics=[]`, `facts=[]`, `topic_method=not_classified`, `extraction_status=pending_extraction`: LLM extraction/объединение новостей в сюжеты будет в следующем PR.
- Для сохранения оригинальной атрибуции дедуплицируются только публикации с одинаковыми **нормализованными текстом, заголовком, URL, опубликованной датой** в пределах одной компании. Однотипный текст из разных источников пока создает два события; объединение связанных событий — отдельная стадия.
- Профиль компании и роль не отправляются в LLM (LLM не вызывается). Пользовательский текст и ссылки не исполняются. `source_url` — справочная ссылка, не точка скачивания.
- При отправке того же payload с тем же `Idempotency-Key` возвращается исходный job, включая итоговый статус. Повтор ключа с другим payload дает 409. Разные ключи могут возвращать разные jobs на одно и то же событие.
- `jobs` доступны **только той демосессии**, которая их создала; `sources/events` доступны другим разрешенным демосессиям **той же компании**, но не других компаний. Это демо-политика, не production RBAC.

## Надежность и эксплуатация

- Задания выбираются compare-and-swap обновлением состояния; на PostgreSQL работают несколько воркеров. Результат и отметка `succeeded` сохраняются в одной транзакции.
- `running` имеет lease 90 сек и атомарно перевыдается после истечения. Максимум 3 попытки; после сбоя результат `failed` с безопасным кодом. Большие генерации LLM требуют отдельного heartbeat/продления lease в следующей итерации.
- Ссылка на исходный документ и `content_hash` сохраняются. При отсутствии новых событий `process_next_job` возвращает False, в режиме daemon воркер спит между опросами.
- `Base.metadata.create_all` — только инициализация MVP, **не миграции**; перед совместной работой с таблицами нескольких версий необходимо внедрить Alembic. Полный тест PostgreSQL/Docker на данном этапе не выполнен (локальные тесты используют SQLite).
- Текущий API не поддерживает RSS, извлечение фактов, API инсайтов или финансовые рекомендации. Их отсутствие нельзя обозначать как готовую функциональность.

## Запуск проверок

```sh
cd backend
python -m pip install -r requirements.txt
pytest -q
```

Контрольные случаи: 202 + последующая обработка, корректная дата UTC, запрет доступа другой компании/сессии, дедупликация с разными idempotency keys, 409 при конфликте, 422 на неверный URL/дату, повторное получение результата, истекшая lease, остановка на третьем сбое, отсутствие выдуманных facts.
